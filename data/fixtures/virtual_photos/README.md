# 사진 AI용 가상 아이 사진

※ 유치온 개발·평가용 가상 자료예요. **모두 AI로 만든 사진이고 실제 원아가 아니에요.** 실제 아이 사진은 이 폴더에 넣지 않아요([기획서](../../../Docs/Step1/기획서.md) NFR-02·D20).

사진 AI(T50: 알림장 사진 정리·우리 아이 찾기, 기획서 FR-23)와 피드 사진 묶기(FR-22)를 만들고 시험할 때 쓰는 사진 295장이에요. 나오는 아이는 시드 아이 21명이고, 같은 아이는 어느 사진에서나 같은 얼굴이에요. 사진마다 누가 나오는지 정답이 `manifest.json`에 있어요.

## 무엇이 있나

| 폴더 | 내용 | 장수 |
| --- | --- | --- |
| `faces/` | 아이마다 정면 1장(`<key>_front.jpg`)·옆모습 1장(`<key>_side.jpg`). 우리 아이 찾기에서 보호자가 등록하는 기준 얼굴로 써요 | 42 |
| `scenes/` | 원 생활 장면. 혼자(`solo-*`)·2~3명(`small_group-*`)·4~6명(`group-*`) | 163 (혼자 84·2~3명 61·4~6명 18) |
| `unknown_kids/` | 명단 21명 **밖의** 아이가 나오는 장면. 정답은 "우리 아이 없음"이라, 어느 아이로 태그해도 오부착이에요 | 21 |
| `no_face/` | 사람 얼굴이 없는 사진(벽 그림·블록·뒷모습·손). "아무도 안 나온 사진"을 거르는지 봐요 | 9 |
| `class_wide/` | 반 전체 행사 사진. 얼굴이 작고 많아 누가 나왔는지 정답을 적지 않았어요 | 10 |
| `blurry/` | `scenes/`에서 고른 사진을 흐리게(초점 흐림 `defocus`)·흔들리게(`shake`) 만든 것. 흐린 사진 묶기에 써요 | 50 |

모두 JPEG이고 긴 변은 1280px 이하예요. 촬영 정보(EXIF)는 지웠어요. 배경 벽의 글씨는 AI가 그린 것이라 읽히지 않는 글자가 섞여 있어요.

## 아이 명단

`manifest.json`의 `children`에 21명이 있어요. `key`·`child_id`는 다른 가상 자료와 같은 값이에요.

- 별빛반(만 4세) 18명: `C4-01` 가온 ~ `C4-18` 로아. `child_id` = `00000000-0000-4000-8000-0000000054NN`. [알림장 명단](../kg-demo-01/daily_notes/roster_c4.json)과 같아요.
- 시드 아이 3명: `SEED-HANEUL` 하늘(별빛반, `…0501`)·`SEED-NOEUL` 노을(별빛반, `…0503`)·`SEED-BADA` 바다(햇님반, `…0502`). 모의 API 시드(`apps/api/app/mock/seed.py`)의 아이예요.

## 정답표 `manifest.json`

```json
{
  "file": "scenes/small_group-002.jpg",
  "kind": "small_group",
  "children": [{"key": "C4-11", "child_id": "00000000-0000-4000-8000-000000005411", "name": "이든"}, …],
  "faces": 3,
  "model": "seedream-5.5 (Higgsfield)",
  "face_check": {"C4-11": 100.0, "C4-18": 100.0, "SEED-NOEUL": 99.7},
  "prompt": "…"
}
```

- `children`: 그 사진에 나오는 명단 속 아이(정답). `unknown_kids`·`no_face`·`class_wide`는 빈 목록이에요.
- `faces`: 사진 속 얼굴 수. 장면·기준 얼굴은 나오는 아이 수이고, Rekognition이 잡은 얼굴 수와 같은 사진만 남겼어요. `unknown_kids`는 Rekognition이 잡은 수, `no_face`는 0, `class_wide`는 `null`(세지 않음)이에요.
- `face_check`: 만들 때 Rekognition `CompareFaces`로 그 아이 정면 사진과 비교한 유사도예요. 장면은 아이마다 95 이상이고 얼굴 수가 아이 수와 같은 것만 남겼어요.
- `blurry`는 `from`(원본 파일)과 `blur`(흐림 종류)가 더 있어요.

## 얼굴 찾기 기준선 `baseline.json`

이 사진으로 Rekognition을 그대로 돌린 결과예요(서울 리전, 2026-11-24). T50에서 만든 기능이 이 숫자보다 나빠지지 않는지 볼 때 써요.

계산 방법: 사진 속 얼굴마다 21명 정면 얼굴과 비교해 가장 비슷한 아이를 고르고, 유사도 80 이상이면 그 아이로 태그해요. 80은 기준선을 재려고 쓴 AWS 기본값이고, 제품에서 쓸 값은 T50에서 이 사진으로 정해요.

다시 재기: `AWS_PROFILE=<팀 프로필> python3 data/fixtures/virtual_photos/make_baseline.py data/fixtures/virtual_photos` (Pillow·AWS CLI 필요, 서울 리전 Rekognition 약 700번 호출 ≈ $0.7).

| 묶음 | 사진 | 정답률(나온 아이를 찾은 비율) | 오부착률(태그 중 틀린 비율) |
| --- | --- | --- | --- |
| 장면(`scenes/`) | 163장·아이 305명 | 97.4% (297/305) | 2.3% (7/304) |
| 옆얼굴(`faces/*_side`) | 21장 | 100.0% | 0.0% |
| 흐린 사진(`blurry/`) | 50장·아이 79명 | 64.6% (51/79) | 5.6% (3/54) |

- 명단 밖 아이(`unknown_kids/` 21장): 얼굴 44개 중 11개(25%)가 명단 속 아이로 태그됐어요. 모두 오부착이에요.
- 얼굴 없는 사진(`no_face/` 9장): 벽 그림 속 얼굴 4개가 잡혔지만 태그는 0개예요.
- 같은 아이일 때 유사도: 중앙값 99.9, 하위 5% 90.7, 최소 7.8, 최대 100.0 (n=381)
- 다른 아이일 때 유사도: 중앙값 52.6, 하위 5% 1.7, 최소 0, 최대 99.8 (n=8478)
- 1등과 2등의 차이(정답일 때): 중앙값 3.7, 하위 5% 0.5, 최소 0.1, 최대 68.0 (n=381)

**다른 아이끼리도 유사도가 높게 나와요.** 어린아이 얼굴은 서로 비슷하게 잡혀서 "기준값 이상이면 태그"만으로는 오부착이 나요. 정답일 때도 1등과 2등의 차이가 중앙값 3.7로 작아서, 차이만으로 자르면 맞는 태그도 많이 버려져요. 그래서 기획서대로 애매한 얼굴은 사람이 확인해요(사진 AI "낮은 신뢰도는 교사 확인", AC-08 "'이 아이 아니에요' 뒤 태그 내려감"). 이 숫자는 어디부터 '애매함'으로 볼지(기준값·1등과 2등 차이)를 T50에서 정할 때 써요.

## 어떻게 만들었나

1. 아이마다 생김새(머리 모양·얼굴형 등)를 정하고 정면 얼굴을 gpt-image-2로 만들었어요. 같은 모델로 정면을 만들어야 아이마다 다른 얼굴이 나와요(Seedream만으로 만들면 다른 아이도 유사도 99 이상으로 거의 같은 얼굴이 나와요).
2. 나머지 사진은 모두 Seedream 5.5(Higgsfield)로 만들었어요. 아이가 나오는 사진은 그 아이의 정면 얼굴을 참고 사진으로 넣었어요.
3. 만든 사진마다 얼굴 수와 아이별 유사도를 검사해 통과한 것만 남겼어요. 떨어지면 최대 3번 다시 만들었고, 3번 다 떨어진 장면 5개는 넣지 않았어요.

피드 시드 사진 5장(`../kg-demo-01/feed_photos/`)도 같은 방법으로 만들었어요. 더 만들 때는 장면 문장(`prompt`)을 참고하세요.

## 쓸 때 지킬 것

- 외부 API(Rekognition 등)에는 이 가상 사진만 보내요. 실제 아이 사진은 보내지 않아요.
- 실제 서비스로 갈 때는 사진·대화 내용처럼 AI로 넘어가는 자료를 모두 앱을 쓰는 사람(보호자·교사·원장 등) 각자의 동의를 받은 뒤에만 보내요(기획서 NFR-02).
- API 이미지(`apps/api/Dockerfile`)에는 들어가지 않아요. 시험·평가에서 레포 경로로 읽어요.
