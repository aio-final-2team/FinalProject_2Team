# 유치온 자체 평가 30문항 (초안 v0.4)

- 목적: 강사님 문서(BFCL-PREPARE) 14절의 **팀 자체 30문항**을 유치온에 맞춰 설계
- 결과 구분: `team_domain` (BFCL 원본 30문항 `bfcl_subset`과 **따로** 보고)
- 상태: 문항·기대값 설계만 함. **아직 모델로 실행하지 않음**
- v0.2 변경: 급식 메뉴 조회 도구 → 통학버스 위치 조회 도구 (YC-N03·N04·M07·F01 교체)
- v0.3 변경: 실행 모델 GPT-6 Luna 하나로 확정 · YC-P04 날씨 → 주식 추천 (날씨는 T15·T52에서 서비스 기능으로 들어감) · YC-N04 기대 응답을 1단계에 맞게 수정 · `urgency`는 기준 확정 전까지 사람 채점 · 도구 표 깨짐 수정
- v0.4 변경:
  - 민원 도구 `prepare_complaint_handoff`(원장 인계) → `prepare_complaint_card`(담임 카드). 원장 보고 여부는 시스템이 정함 (기획서 2.3·FR-07)
  - 통학버스 문항 4개(YC-N03·N04·M07·F01, FR-25 최종 기능)를 MVP 문항으로 교체: 상담 상대 날짜, 지난 알림장, 상담 조건 반영(FR-05·06), 근거 문서 충돌(FR-04). `get_bus_location` 도구 제거 → 도구 7개
  - 질문 속 교사 ID(T-DEMO-01)를 "담임 선생님"으로 바꿔, 시험 상황에서 담임을 찾아내는지도 봄
  - 문의 문항 기대 응답에 출처(문서명·날짜) 표시 추가 (FR-04)
- 같은 내용의 기계용 파일: `2팀_유치온_자체평가_30문항.json` (작성 예정)

## 2. AI에게 줄 도구 7개

조회 도구는 **읽기만**, 준비 도구는 **보내기 전 단계까지만** 해요. 그래서 AI가 "예약됐어요/전달했어요"라고 말하면 틀린 거예요.

| 함수 이름 | 하는 일 | 인자 |
|---|---|---|
| `lookup_notice` | 가정통신문·공지 조회 (읽기만). 결과에 문서명·날짜가 붙음 | kindergarten_id: STRING, topic: ENUM vacation\|field_trip\|fee\|health\|event |
| `get_daily_note` | 우리 아이 알림장 조회 (읽기만) | child_id: STRING, date: STRING YYYY-MM-DD |
| `get_child_photos` | 우리 아이가 나온 사진 조회 (읽기만) | child_id: STRING, date: STRING YYYY-MM-DD |
| `get_consultation_slots` | 상담 가능 시간 조회 (예약 아님) | teacher_id: STRING, date: STRING YYYY-MM-DD |
| `prepare_consultation_request` | 상담 신청서 준비 (교사 승인 전, 확정 아님) | teacher_id: STRING, date: STRING YYYY-MM-DD, time: STRING HH:MM |
| `prepare_absence_notice` | 결석 알림 준비 (보내기 전) | child_id: STRING, date: STRING YYYY-MM-DD, reason: ENUM sick\|family\|other |
| `prepare_complaint_card` | 민원 접수 카드 준비 → 담임 카드로 감 (보내기 전). 같은 내용 3번째·고위험·교사 관련이면 시스템이 원장 보고 카드를 만듦 | category: ENUM safety\|meal\|photo\|teacher\|fee\|other, summary: STRING (사람 검토), urgency: ENUM normal\|urgent |

## 3. 문항 구성

| 유형 | 문항 수 | 확인할 것 |
|---|---:|---|
| 정상 단일 업무 | 10 | 맞는 도구·인자·호출 1번 |

단계: **1단계 판단**은 질문만 주고 고른 도구를 봐요. **2단계 가상응답**은 도구 결과(가짜)를 돌려주고 그다음 행동을 봐요.
