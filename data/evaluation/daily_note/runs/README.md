## ② → ③ 무엇이 바뀌었나

**고친 것(설계 빈틈)**: 자료 AI가 메모를 알림장에 옮기지 않았을 때 검사 AI도 아무 표시를 안 해서 선생님 메모가 사라졌어요. 검사 AI 규칙 한 줄 + 코드 안전장치 + 메모 속 다른 아이 이름 코드 검사를 더했어요. 함정 낱말을 보고 고친 것은 없어요(FB-016-5: 채점 기준을 보고 만든 프롬프트는 개선 근거에서 뺌).

## 알게 된 것
1. **한 번 실행으로는 점수가 흔들려요.** 자료 AI가 같은 입력에 다르게 써서 요청 4개가 바뀌었어요. 비교는 같은 조건으로 3번씩 돌려 평균을 봐야 해요.
2. **보호자 요청 줄에 무엇을 쓸지가 정해지지 않았어요.** 자료 AI 프롬프트는 "요청 내용만 옮긴다"인데, 요청 데이터(#269)의 기대는 "메모대로 답한다"(GR-17·19)예요. 정하고 나서 프롬프트를 고쳐야 해요.
3. 남은 틀림: ND-16 "구석" 표현 그대로, ND-19 다치지 않았는데 `sensitive`(지나친 조심), GR-04·11·15 요청 쪽 확인 항목(빈 메모 날 투약, 다른 날 이야기) 없음.

## ④ 요청 줄 규칙(1안) 뒤 3회

팀 결정(1안): 투약·귀가 요청은 요청을 옮기고(처리 결과는 메모에 있을 때만), 문의는 메모에 있는 사실로만 답하고, 다른 날 이야기는 `date_check`. #269 데이터의 기대를 보고 정한 동작이라, 점수 변화는 '프롬프트 개선 효과'가 아니라 '정한 동작에 맞춘 결과'예요(FB-016-5).

| 문항 | 3회 중 틀림 | 내용 |
| --- | :---: | --- |
| ND-16 반 공통과 섞임 | 3 | "구석에서" 표현을 그대로 씀 |
| GR-04 투약(빈 메모 날) | 3 | 투약 요청 줄은 썼지만 `sensitive` 확인을 안 남김 |
| GR-05 투약(용량 숫자) | 3 | 같음: 투약 요청에 `sensitive` 확인 없음 |
| ND-09·ND-19·GR-18 | 1씩 | 실행마다 다름 |

- 3회 모두 같은 문항이 틀려서 이제 실행 편차보다 **고칠 곳**이 보여요.
- GR-04·05: 검사 AI 규칙의 `sensitive`가 '메모'의 투약만 말하고, '보호자 투약 요청'은 말하지 않아요. 설계 빈틈이라 다음에 고칠 후보예요.
- ND-16: 낙인 표현 다듬기. 규칙 6에 이미 있어서 프롬프트를 더 고치면 함정 낱말에 맞추는 것이 될 수 있어요. 그대로 둘지 팀과 정해요.

## ⑧ → ⑨ 메모 확인 종류와 불필요 표시

종류별 수는 3회 합계예요. 놓침은 정답 확인 종류가 없거나 다른 종류로 대체된 횟수, 불필요 표시는 표시하면 안 되는 메모에 해당 종류가 붙은 횟수예요.

| 확인 종류 | 놓침 ⑧ → ⑨ | 불필요 표시 ⑧ → ⑨ |
| --- | :---: | :---: |
| `sensitive` | 0 → 0 | 4 → 0 |
| `other_child` | 0 → 0 | 0 → 0 |
| `date_check` | 3 → 3 | 0 → 0 |
| `absent` | 1 → 0 | 0 → 0 |
| `not_in_memo` | 0 → 0 | 0 → 0 |

- ⑧의 불필요 `sensitive` 4건은 ND-16(일상 활동을 선택한 메모) 2회와 ND-19(다치지 않은 넘어질 뻔한 상황) 2회예요. ⑨에서는 네 건 모두 사라졌어요.
- ND-09 친구 갈등 메모는 ⑧·⑨ 각 3회에서 통과했어요. 이전 run2의 놓침 원인(메모에는 `other_child`만, 보호자 요청에는 `sensitive`)에 맞춰 두 확인을 서로 대신할 수 없다고 분리해 적었어요.
- 남은 놓침은 ND-15 `date_check` 3회예요. 초안에서 메모가 빠졌을 때 모델이 일반 `sensitive`로 처리해요. 정확한 날짜 근거를 검사 입력에 제공하는 코드 변경은 이번 담당 파일 범위 밖이라 남겼어요.
- ND-16은 ⑨에 `sensitive`가 붙지 않아 종류 판정은 개선됐지만, 자료 AI 문장에 낙인처럼 들리는 "구석"이 남아 문항은 실패했어요. 이 문장 작성 문제는 검사기의 표시 종류와 별개예요.
