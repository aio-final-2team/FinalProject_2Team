# apps/api/app/modules/consultations

`slots.find_consult_slots`가 날짜 하루의 후보를 최대 세 개 계산해요.
근무 시간(`WORK_HOURS`) 안에서 30분씩 나누고 주말·공휴일, 담임의 `staff_busy_blocks`,
확정된 담임·상담실 예약, 다른 요청의 24시간 안 학부모 체크를 빼요.
같은 시작 시각에는 활성 상담실 하나만 골라요. 끝 시각과 다음 시작 시각이 같으면 겹치지 않아요.

현재 요청 대역은 날짜 칸이 없는 HTTP 요청을 받아 내일부터 14일 안의 빠른 후보 세 개를 저장해요.
학부모가 `none_fit`을 보내면 이전 후보를 버리고 같은 요청에서 이미 제시한 시간을 빼서 다시 계산해요.
`preferred_times`의 명시 날짜·요일·다음 주·오늘/내일/모레·시각/범위·오전/오후를 읽고,
겹치는 후보 우선·없으면 가까운 순으로 골라요. 해석하지 못한 문장은 빠른 순서를 쓰고
원문은 이력과 담임(없으면 원장) parent_message 알림에 남겨요. 재제안에도 마지막 희망을 써요.
후보가 없으면 빈 목록을 유지하고 다른 날짜를 묻게 해요. 시간을 만들어 넣지 않아요.
승인된 `slot_unavailable` 규칙의 JSON 객체에서 `after`·`before`가 HH:MM인 값만 읽어요.
다른 사유·잘못된 형식·제안 규칙은 무시해요. after는 근무 시작 기준 30분 칸으로 올려 맞춰요.
규칙 생성·담임 결정은 기억 모듈에 연결돼 있어요. 데모 시드는 별도 바쁜 일정 없이 시작해요.

시간 체크는 요청 → 카드 순서로 잠그고 지금 회차의 후보 1~3개만 받아요.
24시간이 지나고 요청이 awaiting_review이면 체크를 풀고 needs_info로 돌려 담임에게
`slot_hold_expired` 알림 행을 한 번 남겨요. 보류·원장 보고 중에는 건드리지 않아요.
보류 재개·원장 지시 뒤 만료를 검사해요. 원장 보고 중에는 지시 전에 확정하지 못해요.
`cards.book`은 카드 담당 교사·카드 판·학부모 체크를 확인한 뒤 `bookings.book_slot`을 불러요.
다른 반으로 재배정된 교사도 카드 담당이면 확정하고 원장은 대신 확정하지 못해요.
재배정은 살아 있는 후보의 시각·체크를 보존하고 teacher_id를 새 담당으로 맞춰요.
담임 없는 상담 생성은 원장 new_card, 후보가 있으면 학부모 체크를 허용해요.
최종 확정은 요청당 한 건 유니크와 담임·상담실 시간 배제 제약으로 지켜요.
충돌은 409 `SLOT_TAKEN`, 체크하지 않은 후보는 409 `SLOT_NOT_CHOSEN`이에요.
체크할 때도 다른 요청의 확정 예약·24시간 안 체크와 담임 또는 상담실이 겹치면 거부해요.
체크·확정은 담임 → 상담실 순으로 같은 자문 잠금을 잡고, 여러 ID는 정렬해요.
확정 충돌·배제 제약 충돌·예약 INSERT 교착은 충돌 후보만 discarded로 바꾸고 재제안해요.
다른 후보·체크는 보존하며, 재체크 때 살아 있는 이전 후보도 고를 수 있어요.
요청 needs_info·학부모 알림·slot_conflict_reproposed를 저장한 뒤 409 SLOT_TAKEN을 돌려요.
예약 INSERT는 savepoint로 감싸고 승인 없이 카드 판만 올려요. 알림 실패는 재제안도 롤백해요.
상담 dismiss는 chosen_by_parent를 discarded로 풀어요.
원장은 상담 보고 카드만 acknowledge(approvals 0014·report_acknowledged)·hold·resume해요.
보고 보류의 자동 재개도 요청 상태·학부모 표시·알림을 바꾸지 않아요.
체크·확정 모두 이미 시작한 후보는 409 SLOT_PAST로 거부해요.
예약·승인·후보 상태·요청의 approved → sent_or_booked 이력·알림을 같은 트랜잭션에서 저장해요.
알림 저장까지 실패하면 모두 되돌려요. 실제 앱 안 발송은 워커에서 처리해요.

## 상담 종료·지연 알림(T48)

DB Beat가 1분마다 시작이 하루 이내인 확정 예약을 읽고 실제 알림 대상 예약만 잠가요.
종료 10분 전부터 종료 직전까지 담임에게 consultation_ending을 남겨요.
근무 시간 밖에도 생성·발송·재시도는 바로 해요. 종료 뒤에는 보내지 않아요.

[제안] v0.6 `POST /consultations/{booking_id}/delay`는 그 반의 예약 담임만 써요.
expected_end_at을 받아 report_delay로 저장하고 알림을 점검해요. mock도 HTTP로 시연해요.
시작한 상담이고 현재·원래 종료보다 뒤, 원래 종료 + 3시간 이내·같은 KST 날짜여야 해요.
0009 CHECK도 같은 상한을 지켜요. 응답 booking과 affected_bookings는 기록된 예약과
영향받은 뒤 확정 예약 수예요. 발송 완료 수가 아니에요. 실제 종료 입력·화면은 후속이에요.

명시된 지연이 같은 기관·담임 또는 상담실을 쓰는 뒤 예약에 겹치면
그 예약의 담임·신청 학부모에게 consultation_delayed를 남겨요. 앞 학부모·아이 정보는 알리지 않아요.
예상 종료 이후 14일 안의 빈 시간 세 개를 일정·승인 규칙으로 계산해요.
빈 시간이 없으면 다른 날짜를 안내해요. 제안은 예약·체크를 저장하지 않아요.
대체 시간을 받는 예약 변경·취소 경로는 후속 계약이에요.

키에 종료 알림의 예상 종료·지연 알림의 until을 넣어 같은 값은 한 번만 보내요.
지연이 바뀌면 대체 시간을 다시 계산하고 종료 알림도 새 시각에 보내요.
옛 pending은 held로 돌려요. 보낸 알림은 그대로 두고 consultation_reminded에
outcome=superseded·notification_id를 한 번 남겨요. 새 이력에는 until·제안 시각을 남겨요.
발송·재시도도 현재 알림 키와 예약 상태를 검사해요. 발송 기록만 held, 목록 노출은 유지해요.
대체 시간 알림의 교직원 근무 시간 연기는 유지하고 종료 뒤로 미뤄지면 만들지 않아요.

점검과 지연 수정은 같은 자문 잠금으로 직렬화해요. 지연 수정·체크·확정은
요청 → 담임 → 상담실 → 예약 순서로 잠가요. 후보·체크·확정은 연장 구간까지 충돌을 검사해요.
DB 배제 제약 자체는 원래 period를 유지해요. 지연은 기존 뒤 예약과 겹칠 수 있어요.

mock의 대체 후보는 기존 대역처럼 평일 15·16시예요. DB는 근무 시간·수업/회의·예약·체크·승인 규칙을 적용해요.
mock 메모리는 프로세스 간 공유하지 않아 Beat는 DB 워커 모드에서만 실행해요.
