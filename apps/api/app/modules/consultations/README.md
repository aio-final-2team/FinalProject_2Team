# apps/api/app/modules/consultations

`slots.find_consult_slots`가 날짜 하루의 후보를 최대 세 개 계산해요.
근무 시간(`WORK_HOURS`) 안에서 30분씩 나누고 주말·공휴일, 담임의 `staff_busy_blocks`,
확정된 담임·상담실 예약, 다른 요청의 24시간 안 학부모 체크를 빼요.
같은 시작 시각에는 활성 상담실 하나만 골라요. 끝 시각과 다음 시작 시각이 같으면 겹치지 않아요.

현재 요청 대역은 날짜 칸이 없는 HTTP 요청을 받아 내일부터 14일 안의 빠른 후보 세 개를 저장해요.
학부모가 `none_fit`을 보내면 이전 후보를 버리고 같은 요청에서 이미 제시한 시간을 빼서 다시 계산해요.
`preferred_times`의 자유 문장은 이력으로만 남겨요. 자연어 날짜·시간 해석은 요청 그래프에서 이어가요.
후보가 없으면 빈 목록을 유지하고 다른 날짜를 묻게 해요. 시간을 만들어 넣지 않아요.
승인된 `slot_unavailable` 규칙의 JSON 객체에서 `after`·`before`가 HH:MM인 값만 읽어요.
다른 사유·잘못된 형식·제안 규칙은 무시해요. after는 근무 시작 기준 30분 칸으로 올려 맞춰요.
규칙 생성·담임 결정은 기억 모듈에 연결돼 있어요. 데모 시드는 별도 바쁜 일정 없이 시작해요.

시간 체크는 요청 → 카드 순서로 잠그고 지금 회차의 후보 1~3개만 받아요.
24시간이 지나고 요청이 awaiting_review이면 체크를 풀고 needs_info로 돌려 담임에게
`slot_hold_expired` 알림 행을 한 번 남겨요. 보류·원장 보고 중에는 건드리지 않아요.
보류 재개·원장 지시 뒤 만료를 검사해요. 원장 보고 중에는 지시 전에 확정하지 못해요.
`cards.book`은 우리 반 담임·카드 판·학부모 체크를 확인한 뒤 `bookings.book_slot`을 불러요.
다른 반으로 재배정된 교사와 원장은 대신 확정하지 못해요.
최종 확정은 요청당 한 건 유니크와 담임·상담실 시간 배제 제약으로 지켜요.
충돌은 409 `SLOT_TAKEN`, 체크하지 않은 후보는 409 `SLOT_NOT_CHOSEN`이에요.
체크할 때도 다른 요청의 확정 예약·24시간 안 체크와 담임 또는 상담실이 겹치면 거부해요.
체크·확정은 담임 → 상담실 순으로 같은 자문 잠금을 잡고, 여러 ID는 정렬해요.
배제 제약 충돌·예약 INSERT 교착은 409 SLOT_TAKEN으로 돌려요.
체크·확정 모두 이미 시작한 후보는 409 SLOT_PAST로 거부해요.
예약·승인·후보 상태·요청의 approved → sent_or_booked 이력·알림을 같은 트랜잭션에서 저장해요.
알림 저장까지 실패하면 모두 되돌려요. 실제 발송은 워커 항목에서 연결해요.
