# 3단계 복합 요청 부분 답 구현

## 변경한 동작

`answer.py`가 작성 모델의 `partial`·`unanswered[]`를 받는다. 부분 답의 사실은 각각 한 문장짜리 `facts[] {text, evidence[]}`로 구성하고, 각 인용이 실제 검색 조각에 있는지 코드가 검증한다. 인용이 하나라도 없거나 미답 구절이 질문 원문 안에 없으면 부분 초안을 만들지 않는다. 확인된 사실 문장만 checker 검사를 거치고, 미답마다 코드가 “질문하신 ‘…’에 대해서는 자료에서 확인하지 못했어요. 선생님이 확인한 뒤 알려 드릴게요.”를 덧붙인다.

협업 그래프는 일부 근거가 있는 `no_evidence=true` 초안을 checker로 보내고, 통과하면 카드 초안에 보존한다. 전체 근거 없음과 충돌은 기존대로 빈 초안으로 담임에게 넘긴다. 요청 카드 생성 경계도 부분 답에 한해 본문을 지우지 않는다. 부분 여부는 그래프 내부에서만 사용하고 카드 JSON에는 새 필드를 저장하지 않는다. 카드에는 기존 `no_evidence` 경고와 인용 근거가 표시된다. 학부모 자동 발송 경로는 추가하지 않았다.

## G1형 가짜 모델 예시

입력: “재롱잔치 날짜랑 준비물이랑 그날 하원 시간 바뀌는지 알려주세요”

테스트 초안:

> 재롱잔치는 12월 12일이고 준비물은 흰 양말이에요.
> 질문하신 ‘그날 하원 시간 바뀌는지’에 대해서는 자료에서 확인하지 못했어요. 선생님이 확인한 뒤 알려 드릴게요.

이는 단위 시험의 고정 가짜 근거·모델 출력이며, 실제 모델 재실측 결과가 아니다.

## 호환성·안전 경계

- API 카드 JSON 스키마에 `partial`·`unanswered` 필드는 추가하지 않았다. 기존 `text`, `no_evidence`, `conflict`, 인용 관계와 경고만 사용한다.
- 부분 답도 `no_evidence=true`라 `staff_ask`가 학부모/교직원 자동 답변으로 반환하지 않는다.
- `conflict`가 있으면 부분 텍스트를 보존하지 않고 기존 충돌 처리로 빈 초안을 만든다.
- 실제 G3 실측에서 evidence에 없는 추가 문장이 나와 문장별 인용 구조를 강화했다. 새 구조는 가짜 모델 시험으로 검증했으나, 이 강화 이후 실제 모델 결과는 없다.
- 일반 답변·문서 검사·카드 승인 동작에 대한 DB/API 회귀 시험을 실행했다.
