# 3단계 복합 요청 부분 답 설계

## 확인한 현재 동작

`request_collaboration.build_graph()`는 `document_write` 결과의 `no_evidence`가 참이면 `handoff`로 이동한다. `handoff()`는 카드에 넘기는 `text`를 빈 문자열로 만들고 `evidence`만 보존한다. 이 때문에 G1~G3처럼 일부 질문에 인용 근거가 있어도 초안 본문이 사라진다. 근거가 있는지 여부를 복합 질문 전체에 하나의 불리언으로 표현하고, 부분별 답/미답을 전달하는 필드가 없다.

`answer.py`도 읽기 전용이라 원인 확인만 했다. `_verify()`는 일부 근거가 있어도 `no_evidence=true`이면 전체 답을 `NO_ANSWER`로 바꾸므로, 작성 프롬프트만 바꿔서는 부분 초안을 보존할 수 없다.

## 구현 제안 (현재 허용 범위 밖)

1. 질문의 독립된 항목별로 답 가능한 사실과 누락 항목을 구분하는 응답 구조를 정한다. 확인된 사실마다 기존처럼 실제 조각 인용을 붙이고, 미답에는 “선생님이 확인 후 알려 드릴게요” 같은 안내만 둔다.
2. `answer.py`의 검증·정규화가 일부 인용 근거가 있을 때 유효한 부분 초안을 보존하고, 미답 존재 여부를 별도 필드로 반환하도록 확장한다. 전체 근거 없음과 부분 근거를 혼동하지 않도록 `no_evidence` 의미를 명확히 한다.
3. `request_collaboration.py`에서 부분 초안을 빈 문자열로 지우지 않고 담임 확인 카드에 전달한다. 부분 미답 경고는 유지하고, `conflict`가 있으면 기존 안전한 충돌 처리 우선순위를 유지한다. 카드 생성은 지금처럼 담임 승인 대기이며 학부모 자동 발송은 추가하지 않는다.
4. 가짜 모델 단위 시험에서 G1형 혼합 질문에 근거 있는 답·인용·미답 안내·`no_evidence` 경고·`teacher_review` 카드가 함께 남는지 검증한다. 충돌 답변 회귀도 기존 기대를 유지한다.

## 수정 제한

`agents/graphs/request_collaboration.py`와 `agents/graphs/answer.py`는 지시서에서 읽기 전용으로 지정되어 있어 수정하지 않았다. 따라서 G1~G3 동작은 이번 변경에서 고쳐지지 않았으며 위 두 파일의 권한이 있는 변경 작업이 필요하다.
