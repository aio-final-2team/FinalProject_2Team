# 피드백 처리 방법

강사님·멘토님·팀원 피드백을 한 곳에 모으고, 누가 무엇을 할지 자동으로 나누는 방법입니다. 피드백이 여러 곳에서 계속 들어오고 기획서·WBS·보드를 그때마다 고쳐야 해서, 피드백이 들어오는 곳과 문서를 고치는 사람을 하나로 정했습니다.

정리하면 이렇습니다. 피드백을 디스코드 `#피드백`에 올리면 봇이 번호를 매기고 담당자를 멘션합니다. 담당자는 `[문서]` 항목이면 메모 PR을, `[작업]` 항목이면 작업 PR을 올립니다. 지혜님은 메모를 모아 기획서·WBS에 반영합니다.

이 문서를 AI에게 그대로 넣고 일을 시켜도 됩니다. 그때 AI가 지킬 규칙은 [7. AI에게 맡길 때](#7-ai에게-맡길-때)에 있습니다.

## 1. 전체 흐름

| 단계 | 누가 | 무엇을 |
| --- | --- | --- |
| 1 | 피드백을 받은 사람 | `#피드백` 채널에 올립니다. 첫 줄에 누가 준 피드백인지 적습니다. |
| 2 | 봇(`태웅's 클로드`) | 1분 안에 그 글에 스레드를 열고, 번호를 매기고, 할 일을 항목별로 나눠 담당자를 멘션합니다. |
| 3 | 담당자 | `[문서]`는 자기 폴더에 메모를 써서 PR, `[작업]`은 작업한 PR 본문에 번호를 적습니다. |
| 4 | 지혜님 | `[문서]` 메모를 모아 기획서·WBS·GitHub Projects에 반영합니다. |
| 5 | 누구나 | 작업하다 생긴 문제도 다시 `#피드백`에 올립니다. 그러면 1단계부터 같은 흐름으로 돕니다. |

기획서·WBS 원본(`Docs/Step1`)은 지혜님만 고칩니다. 다른 사람은 메모만 쓰기 때문에 PR끼리 겹치지 않습니다.

## 2. 피드백 올리기

- 채널에 바로 올립니다. 스레드 안에 쓴 글은 봇이 읽지 않습니다.
- 첫 줄에 출처(강사님·멘토님·팀원 이름)를 적습니다. 나머지는 자유롭게 써도 됩니다. 번호가 매겨져 있으면 그 번호대로 나눕니다.
- 사진(캡처)도 읽습니다. 글이 길면 `.md`나 `.txt` 파일(50KB까지)로 첨부해도 됩니다. 그 밖의 파일은 읽지 못합니다.
- 이미 끝낸 항목은 "6번은 이미 했어요"처럼 적어 주면 할 일에서 빼고 따로 표시합니다.
- 인사, "확인했습니다" 같은 답장, 일정 공지에는 반응하지 않습니다. 채널에서 짧게 이야기해도 괜찮습니다.
- 다른 봇이나 자동화(웹훅)가 올린 글도 똑같이 처리합니다. 봇이 스스로 단 글에는 반응하지 않습니다.

예시:

```
강사님 일일 피드백 11/17
1. 화면·API·도구·평가 문항의 이름과 형식을 맞춰 주세요. …
2. 기획서·WBS의 2차 보완을 실제 수정본으로 마무리해 주세요. …
6. 모델 선택은 정확도·시간·비용을 함께 보고 결정해 주세요. …
6번은 이미 했어요.
```

## 3. 봇이 다는 글 읽기

```
FB-001 · 11/18 · 출처: 강사님 · 올린 분: 태웅

FB-001-1 [작업] 도구·API·평가 문항 이름과 형식을 계약표 기준으로 맞추기
→ @태웅 · WBS T10 입출력 계약 합의, T13 API 설계 문서

FB-001-2 [문서] 기획서·WBS 2차 보완 수정본 마무리하기
→ @지혜 · 기획서 표지·9 일정과 역할, WBS T02

이미 했다고 적힌 것: 6번
참고: 원문만으로는 애매한 점
```

- **번호**: `FB-001`은 피드백 한 건, `FB-001-2`는 그 안의 두 번째 할 일입니다. 번호는 계속 이어집니다.
- **`[문서]` / `[작업]`**: 기획서·WBS 문구를 바꿔야 끝나는 일이면 `[문서]`, 기획서·WBS는 그대로 두고 작업만 하면 끝나는 일이면 `[작업]`입니다. 둘 다 해당하면 `[문서]`입니다.
  - `[문서]` 예: 기획서 위험 표에 행 추가, 결정 기록 칸 채우기, WBS 일정·담당 바꾸기
  - `[작업]` 예: API·도구 이름 맞추기, DB 시험 기록 남기기, `Docs/Step2` 설계서 고치기, 코드 수정
- **담당**: 봇이 관련 WBS 작업의 담당자로 정합니다. 없으면 역할로 정하고, 그래도 애매하면 지혜님으로 정한 뒤 "(담당 확인 필요)"를 붙입니다.
- **고칠 곳**: `develop` 브랜치 `Docs/Step1`의 `유치온_기획서_MMDD.md`·`유치온_WBS_MMDD.md` 중 날짜가 가장 큰 파일에서 절 번호, 요구사항 ID(FR·NFR·AC), WBS 작업 ID를 찾아 적습니다.
- **참고**: 원문만으로 판단하기 어려운 점입니다. 담당자가 확인하면 됩니다.

## 4. 담당자가 할 일

### `[문서]` 항목 — 메모 PR

자기 폴더에 항목 번호로 `.md` 파일을 만들어, 평소처럼 자기 브랜치에서 `develop`으로 PR을 올립니다. 기획서·WBS 원본은 고치지 않고, 바꿀 문장만 그대로 적습니다. 지혜님이 그 문장을 옮겨 붙입니다.

| 폴더 | 담당 |
| --- | --- |
| `Docs/Feedback/jihye` | 박지혜 |
| `Docs/Feedback/taewoong` | 문태웅 |
| `Docs/Feedback/youngmin` | 손영민 |
| `Docs/Feedback/sungju` | 차성주 |
| `Docs/Feedback/inhye` | 김인혜 |

메모 양식(`Docs/Feedback/taewoong/FB-001-5.md` 예시):

```
피드백: FB-001-5
고칠 곳: 기획서 11장 결정 기록 표 '배포 서버' 행, 마지막 칸
바꾸기 전: AWS 구성·비용·비밀값·백업·복구와 웹 배포 URL의 확인 근거를 기록
바꾼 후: 비용 근거(11/18 기준). EC2 t3.large $0.104/시간 × 1,152시간 ≈ $120, …
```

"바꾸기 전"에는 지금 문서에 적힌 문장을 그대로 복사하고, "바꾼 후"에는 대신 들어갈 문장을 씁니다. 새 행을 추가하는 거면 "바꾸기 전"에 `(없음)`이라고 씁니다. 고칠 곳이 여러 군데면 `## 1`, `## 2`처럼 나눠서 한 파일에 씁니다.

### `[작업]` 항목 — 작업 PR에 번호

메모 없이 작업합니다. 작업한 PR 본문(템플릿의 "연결 이슈" 칸)에 번호를 한 줄 적습니다.

```
피드백: FB-001-1
```

### 담당이 잘못 잡혔을 때

스레드에 맞는 사람을 멘션해서 넘깁니다. 봇은 같은 글을 다시 나누지 않으니, 넘겨받은 사람이 그대로 처리하면 됩니다.

## 5. 지혜님이 할 일

`[문서]` 메모 PR을 보고 기획서·WBS·GitHub Projects에 반영한 뒤 메모 PR을 머지합니다. 반영하지 않기로 했으면 PR에 이유를 남깁니다.

## 6. 봇이 반응하지 않을 때

- 1분이 지나도 스레드가 생기지 않으면, 채널에 바로 올렸는지(스레드 안이 아닌지) 확인합니다. 인사나 공지처럼 보이는 글이면 피드백으로 보지 않습니다.
- 봇은 1분마다 다시 시도합니다. 세 번 시도해도 나누지 못하면 봇이 "자동으로 못 나눴어요. 지혜님이 직접 나눠 주세요."라고 남깁니다.
- 그 밖의 문제는 태웅에게 알려 주세요.

## 7. AI에게 맡길 때

이 문서와 함께 **봇 스레드의 내 항목 줄**과 **피드백 원문**을 붙여 넣고 이렇게 시키면 됩니다.

- "FB-001-3이 내 `[작업]` 항목이야. 이 규칙대로 작업하고 PR 본문까지 써줘."
- "FB-002-1 `[문서]` 메모를 양식대로 써줘. 강사님 원문은 이거야: …"

AI가 지킬 규칙:

1. `Docs/Step1`의 기획서·WBS 원본 파일은 고치지 않는다. 바꿀 문장은 메모로만 쓴다.
2. `[문서]` 메모는 `Docs/Feedback/<담당자 폴더>/<항목 번호>.md`에 위 양식(피드백·고칠 곳·바꾸기 전·바꾼 후)으로 쓴다. 담당자 폴더는 4절 표에서 찾는다. "바꾸기 전"은 `develop` 브랜치 `Docs/Step1`의 날짜가 가장 큰 기획서·WBS 파일에서 문장을 그대로 복사한다.
3. `[작업]`은 메모를 만들지 않고, 작업 PR 본문에 `피드백: <항목 번호>`를 적는다.
4. PR은 자기 브랜치에서 `develop`으로 올린다. `main`에는 올리지 않는다.
5. 다른 사람 폴더의 파일은 건드리지 않는다.
6. 비밀값(API 키·비밀번호)이나 실제 아이(원아) 정보는 넣지 않는다.
7. "바꾼 후"에 넣을 숫자·사실이 원문이나 문서에 없으면 지어내지 말고 사용자에게 묻는다.
8. PR은 사용자가 내용을 확인한 뒤에 올린다.
