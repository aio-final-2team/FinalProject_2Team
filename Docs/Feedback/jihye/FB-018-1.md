피드백: FB-018-1 [문서] 알림장 중심 첫 시연 범위를 기획서·WBS에 맞추기

한 일: 기획서 Word·Markdown과 WBS Excel·Markdown에 11/20 합의를 반영했다. [T12 화면 지도](../../Step2/유치온_T12_화면지도.md)와 [알림장 에이전트 흐름 §7.1](../../Step2/알림장_에이전트_흐름.md)도 같은 시연 순서로 맞췄다. [PR #295](https://github.com/aio-final-2team/FinalProject_2Team/pull/295)는 [T22 #179](https://github.com/aio-final-2team/FinalProject_2Team/issues/179)의 멘토링 보고 근거다.

기획서·WBS 반영:

- 고칠 곳: 기획서 §2.2 MVP 범위 표의 시연 기준
- 바꾸기 전: 중간 발표엔 자기 검사를 하는 에이전트와 사람 승인을 민원 흐름부터 안정적으로 보여 줌(가이드: 핵심 기능 1개 이상 안정 시연). 다섯 에이전트 협업은 STEP 4(12/11). 데이터는 가상 원 자료만
- 바꾼 후: 중간 발표는 담임의 알림장 초안·검사·확인 흐름을 중심으로 시연한 뒤 문의 답변 초안 확인을 보여 준다(D02). 사진 AI는 최종 선택 기능으로 가상 자료 시연 또는 목업 범위에서 소개한다. 다섯 에이전트 협업은 STEP 4(12/11)다.

- 고칠 곳: 기획서 §2.3 먼저 검증할 흐름
- 바꾸기 전: 강사님 11/13 피드백대로, 한 요청이 학부모 → 담임 → 원장으로 이어지는 흐름부터 끝까지 돌린다. 팀 자체 평가 문항도 이 두 흐름에서 시작한다. 중간 발표(12/08)는 민원 흐름을 메인으로, 상담 거절→재제안을 이어서 보여 준다.
- 바꾼 후: 11/20 팀 결정에 따른 첫 시연 순서는 ① 담임의 알림장 AI 초안 ② 문의 답변 초안 확인 ③ 사진 AI다. 사진 AI는 가상 자료를 쓰고 실제 호출이 확인되기 전에는 목업으로 보여 준다. 민원·상담은 후속 검증 흐름으로 기록한다.

- 고칠 곳: 기획서 §3 FR-10 수용 기준
- 바꾸기 전: 교사 입력(활동·준비물)과 원 자료(식단·일정), 요청 기록(투약·귀가)으로 아이별 초안을 만듦. 확인 필요 항목이 남으면 발송이 잠기고, 교사 확인 후에만 보내짐
- 바꾼 후: 반 활동·준비물, 아이별 관찰 메모, 원 자료(식단·일정)와 그날 보호자 요청을 참고해 아이별 글 초안을 작성한다. 검사 AI가 메모·요청과 대조한다. 확인 필요 항목이 남으면 발송이 잠기며 담임 확인 후에만 발송한다. 첫 시연의 중심 기능이다.

- 고칠 곳: 기획서 §3 FR-15 수용 기준
- 바꾸기 전: 교사가 올린 사진에서 흐린 사진을 빼고 아이별로 나눔(가상 아이 사진만). 사진 카드 승인 전에는 어느 가정에도 보이지 않음
- 바꾼 후: 교사가 올린 가상 사진에서 흐린 사진을 빼고 아이별로 나눈다. 사진 카드 승인 후 해당 가정에 공개한다. 첫 시연에서 사진 AI를 소개할 때 실제 호출 미확인 상태면 목업을 사용한다.

- 고칠 곳: 기획서 §11 결정 기록 D02 선택지
- 바꾸기 전: A · 민원 흐름 메인 + 상담 거절→재제안
- 바꾼 후: 담임의 알림장 AI 초안 → 문의 답변 초안 확인 → 사진 AI

- 고칠 곳: WBS T40 완료 기준
- 바꾸기 전: AC-01(민원→원장 보고)을 메인으로, AC-02(상담 거절→재제안)·AC-03·AC-04를 시연하고 질문 대비 자료가 있음
- 바꾼 후: 담임의 알림장 초안·확인·발송 잠금(AC-04)을 중심으로, 문의 답변 초안 확인(AC-03)을 이어서 보여 준다. 사진 AI는 가상 자료를 쓰고 실제 호출 미확인 시 목업으로 소개한다(FB-018-1, D02). 민원·상담은 후속 검증·질문 대비 자료에 둔다.

- 고칠 곳: WBS T42 완료 기준
- 바꾸기 전: 최종 기능의 순서·담당이 기록됨
- 바꾼 후: 첫 시연 피드백을 바탕으로 알림장·문의·사진 AI와 후속 검증 흐름의 최종 순서·담당·완료 기준을 결정 기록에 남긴다. 사진 AI의 실제 호출 여부와 목업 범위를 구분한다.
