| 항목 | 내용 |
| --- | --- |
| 작업 | T10 입출력 계약 합의(데이터→백엔드→에이전트→화면) (#167) |
| 작성 | 태웅 · 회의 2026-11-18 · 합의 대상 5명 전원 |
| 판 | 회의 전 초안 3 · 2026-11-17 (T04 대조 검토 반영) |
| 함께 볼 것 | [DB 스키마 설계서](DB_스키마_설계서.md) · T04 흐름·권한 명세(성주, 11/17 팀 합의, PR #234) |

상태 이름·화면 표시 이름·역할별 권한은 T04를 그대로 따른다. 회의에서 이 표의 필드·권한·오류 형식을 정하면, T13(11/19~20)에서 `contracts/openapi.yaml`과 모의 API로 옮긴다. 화면은 `openapi-typescript`로 이 파일에서 타입을 만든다. 경로 이름은 예시이고 T13에서 확정한다.

## 1. 공통 규칙

| 항목 | 정할 안 |
| --- | --- |
| 인증 | 모든 API는 `Authorization: Bearer <JWT>`. 쿠키는 쓰지 않음(Android 앱·웹 공용) |
| ID | 요청·카드·계정은 UUID 문자열. 이력·알림은 정수 |
| 시각 | ISO 8601, 한국 시간 오프셋 포함(예: `2026-12-01T15:00:00+09:00`) |
| 목록 | `?limit=20&cursor=<다음 커서>` → `{ "items": [...], "next_cursor": "..." }` |
| 같은 제출 두 번 | 요청 만들기는 화면이 만든 `client_request_id`를 꼭 보냄. 같은 값이면 처음 만든 요청을 그대로 돌려줌 |
| 카드 결정 | 화면이 본 카드 `version`을 같이 보냄. 그사이 카드가 바뀌었으면 409 |
| 다른 기관·다른 반 자료 | 있는지 없는지도 알리지 않도록 404로 답함(권한 거부는 이력에 남김) |
| CORS 허용 | 웹 배포 주소 + Capacitor 앱(`https://localhost`, `capacitor://localhost`) |

### 1.1 오류 응답 형식 (모든 API 공통)

```json
{
  "error": {
    "code": "CARD_VERSION_CONFLICT",
    "message": "다른 사람이 먼저 카드를 처리했어요. 새로고침해 주세요.",
    "trace_id": "8f2c…",
    "details": { "current_version": 3 }
  }
}
```

| HTTP | `code` 예 | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 필드 형식이 틀림. `details.fields`에 칸 이름 |
| 401 | `UNAUTHENTICATED` | 토큰 없음·만료·무효 |
| 403 | `FORBIDDEN_ROLE` | 역할상 못 하는 일(예: 학부모가 카드 결정) |
| 404 | `NOT_FOUND` | 없거나, 다른 기관·반 자료 |
| 409 | `CARD_VERSION_CONFLICT` · `SLOT_TAKEN` · `SLOT_NOT_CHOSEN` · `ALREADY_DECIDED` · `INVALID_TRANSITION` · `NOTE_BATCH_BLOCKED` | 동시 처리·예약 겹침·학부모가 체크하지 않은 시간 확정·이미 결정됨·T04 전이 규칙에 없는 상태 변경·반에 아직 확인 안 된 알림장이 있어 일괄 발송 잠김(`details.blocked[]`) |
| 422 | `NEEDS_INFO` | 필수 정보가 빠짐. `details.missing_fields`에 물어볼 항목 |
| 503 | `UPSTREAM_UNAVAILABLE` | 모델·외부 API 장애. 요청은 저장되고 나중에 다시 처리 |

`message`는 화면에 그대로 띄울 수 있는 한국어 문장으로 쓴다. `trace_id`는 이력·LangSmith에서 같은 호출을 찾는 값이다.

## 2. 화면 ↔ 백엔드

### 2.1 학부모

| 하는 일 | 보냄 | 받음 | 권한 |
| --- | --- | --- | --- |
| 로그인 | `login_id`, `password` | `access_token`, `user { id, role, display_name, org_id }`, `children[]` | 전체 |
| 요청 만들기 | `client_request_id`, `type`, `body`, `child_id`, `previous_request_id?`(끝난 요청을 다시 열 때, T04 2.1) | `request { id, status, missing_fields[] }` | 학부모 |
| 내 요청 목록 | `status`(선택) | `items[] { id, type, title, status, status_label, updated_at, next_action, hold_until? }` — `status_label`은 T04 2장 학부모 표시 이름 | 자기 요청만 |
| 요청 상세 | — | `request`, `messages[]`, `timeline[] { label, at }`, `consultation?` — `timeline`은 학부모용 요약(T04 7.1). 상태가 바뀐 단계만 학부모 표시 이름으로 주고, 위험 등급·보류 이유·도구 호출·처리한 교직원은 넣지 않음 | 자기 요청만 |
| 대화 이어 쓰기 | `body` | `message { id, sender_type, body, created_at }` | 자기 요청만 |
| AI 진행 보기(스트리밍) | — | SSE 이벤트(3장) 중 `stage`·`done`·`error`만. 답변 글자(`token`)는 보내지 않음 | 자기 요청만 |
| 상담 가능 시간 체크 | `slot_ids[]`(1~3개) 또는 `none_fit: true`(다른 시간 필요) + `preferred_times` | `slots[] { id, status: "chosen_by_parent" }` → 요청은 `awaiting_review`. `none_fit`이면 후보를 다시 계산 | 자기 요청만 (T04 합의 1) |
| 민원 회신 '확인했어요' | — | `request { status, parent_confirmed_at }` | 자기 민원만 (T04 합의 2) |
| 알림 목록·읽음 | `notification_id` | `items[] { id, kind, title, body, request_id, subject_type?, subject_id?, read_at }` — `kind`는 T04 9장 11가지, 알림장 알림은 `subject_type = "daily_note"` | 자기 알림만 |

## 3. AI 진행 스트리밍 (SSE)

| 항목 | 안 |
| --- | --- |
| 경로 예 | 학부모 `GET /requests/{id}/stream` · 교직원 카드 화면 `GET /cards/{id}/stream` |
| 읽는 법 | 토큰을 헤더로 보내야 하므로 브라우저 `EventSource` 대신 `fetch` 스트림으로 읽음 |
| 이벤트 | `stage`(단계 바뀜) · `token`(답변 글자) · `card`(카드가 생김) · `done`(끝) · `error`(오류, 1.1과 같은 형식) |
| 누가 무엇을 받나 | 학부모 스트림은 `stage`·`done`·`error`만. `token`·`card`는 교직원 카드 화면 스트림에서만 보낸다. 담임 승인 전 초안이 학부모에게 나가지 않게 하기 위해서다(T04 3.2 자동 회신 금지, 5.2 첫 답은 담임 승인) |

```text
event: stage
data: {"stage": "searching", "label": "근거 문서를 찾고 있어요", "at": "2026-12-01T10:00:02+09:00"}

event: token                       ← 교직원 카드 화면 스트림만
data: {"text": "12월 체험학습은 "}

event: done
data: {"request_status": "awaiting_review"}
```

`stage` 값은 요청 상태가 아니라 AI 처리 단계다. `classifying`(분류) · `searching`(근거 검색) · `drafting`(초안) · `checking`(검사)을 쓰고, 끝나면 바뀐 요청 상태를 `done.request_status`로 보낸다(T04 1장 "상태가 아니라 진행 표시", NFR-10).

## 4. 백엔드 ↔ 에이전트 (Function Calling 도구)

에이전트는 기관이 고정된 서비스 권한으로 도구를 부른다. 도구는 DB를 직접 열지 않고 백엔드 함수를 거친다. 모든 도구 호출은 `events`에 `tool_called` 또는 `tool_failed`로 남는다.

| 도구 | 부르는 AI | 받는 값 | 돌려주는 값 |
| --- | --- | --- | --- |
| `route_request` | 감독 | `request_id` | — (아래 분류 결과를 저장) |
| `create_card` | 감독·자료 | `request_id`, `kind`, `assignee_id`(원장 보고 카드 = 원장 ID. 담당을 못 정하면 비움 → 받은함 '미배정'), `draft`, `evidence[]` | `card_id` |
| `notify_staff` | 감독 | `card_id`, `reason` | `notification_id` |
| `search_documents` | 자료 | `query`, `classroom_id?`, `doc_types[]?`, `top_k` | `chunks[] { chunk_id, document_title, location, effective_from, content, score }` |
| `get_law_article` | 자료 | `law_name`, `article` | `text`, `source_url`, `fetched_at` |
| `get_memory` | 기억 | `owner_id`, `kinds[]` | `memories[] { kind, reason_code, content, structured }`, `active_rules[]` |
| `propose_rule` | 기억 | `owner_id`, `reason_code`, `rule_text`, `rule_json` | `rule_id` 또는 이미 있으면 기존 `rule_id` |
| `check_draft` | 검사 | `card_id` 또는 `note_id`(아이별 알림장) | — (아래 검사 결과를 저장. 알림장이면 `open_checks`) |
| `return_to_step` | 검사 | `card_id`, `step`, `issues[]` | `attempt`(1·2). 3번째면 오류 대신 사람 카드로 넘김 |
| `find_consult_slots` | 코드 | `request_id`, `teacher_id`, `from`, `to`, `rules[]` | `slots[] { slot_id, period, room, round, rank }` (회차마다 최대 3개. 다시 내면 `round` + 1) |

### 4.1 에이전트가 내는 결과 형식

| 결과 | 필드 |
| --- | --- |
| 분류(감독 AI) | `type`, `urgency`(`low`·`normal`·`high`·`urgent`), `topic_key`, `assignee_role`, `missing_fields[]`, `handoff_reason?`(모호·긴급·고위험이면 사람에게 바로). 민원이면 `risk_level`(`normal`·`urgent`·`uncertain`), `risk_category?`(긴급 4가지), `risk_confidence`(0~1), `repeat_count`(같은 반·30일·같은 주제) |

## 6. 회의에서 정할 것

T04에서 이미 정해진 것(상담은 학부모가 먼저 체크, 민원 완료 순서, 같은 내용 범위 30일, 위험 등급 3단계, 받은함 필터 6개, 알림장 일괄 발송, 원에 남은 답 조건)은 다시 다루지 않는다.

1. 1.1 오류 `code` 목록과 화면 문구를 누가 쓰는지
2. 거절·반려 이유 코드(`reason_code`) 목록
3. `topic_key` 만드는 기준(감독 AI가 주제를 어떻게 붙이는지)
4. 카드 종류별 처리 기한(`due_at`). 원장 현황의 '지연' 기준
5. SSE `stage` 문구를 화면이 쓸지 서버가 보낼지
6. 학부모가 상담 시간을 체크한 뒤 담임 확정까지 그 시간을 잡아 둘 시간
7. 4장 도구 이름(기획서 6장의 예시 이름 + `find_saved_answer`)을 이대로 확정할지
8. T04 후속 F1: 학부모 미확인이어도 담임이 이유를 남기고 처리 완료할 수 있게 할지
9. 같은 질문 여러 건을 카드 한 장으로 묶을지(T04 5.2 제안). 묶으면 회신 API가 요청 여러 건에 한 번에 보냄
10. 보류 카드를 예정일(`hold_until`)에 시스템이 자동 재개할지, 담당이 `resume`을 눌러야만 재개할지
11. `urgency = urgent`와 민원 위험 등급 `urgent`가 둘 다 '긴급'이다. 받은함 맨 위는 위험 등급 하나로 두고, `urgency`는 화면에서 '급한 정도'로 따로 부를지(T04에 없는 칸)
12. 요청 없는 카드(알림장 묶음·규칙 제안)를 받은함 '확인 필요'에 넣을지(T04 2.2 표에 없음)
