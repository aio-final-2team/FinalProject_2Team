# 유치온 입출력 계약표 초안 (T10 회의용)

| 항목 | 내용 |
| --- | --- |
| 작업 | T10 입출력 계약 합의(데이터→백엔드→에이전트→화면) (#167) |
| 작성 | 태웅 · 회의 2026-11-18 · 합의 대상 5명 전원 |
| 판 | 회의 전 초안 · 2026-11-17 |
| 함께 볼 것 | [DB 스키마 설계서](DB_스키마_설계서.md) · T04 흐름·권한표(지혜) |

회의에서 이 표의 필드·권한·오류 형식을 정하면, T13(11/19~20)에서 `contracts/openapi.yaml`과 모의 API로 옮긴다. 화면은 `openapi-typescript`로 이 파일에서 타입을 만든다. 경로 이름은 예시이고 T13에서 확정한다.

## 1. 공통 규칙

| 항목 | 정할 안 |
| --- | --- |
| 인증 | 모든 API는 `Authorization: Bearer <JWT>`. 쿠키는 쓰지 않음(Android 앱·웹 공용) |
| ID | 요청·카드·계정은 UUID 문자열. 이력·알림은 정수 |
| 시각 | ISO 8601, 한국 시간 오프셋 포함(예: `2026-12-01T15:00:00+09:00`) |
| 목록 | `?limit=20&cursor=<다음 커서>` → `{ "items": [...], "next_cursor": "..." }` |
| 같은 제출 두 번 | 요청 만들기는 화면이 만든 `client_request_id`를 꼭 보냄. 같은 값이면 처음 만든 요청을 그대로 돌려줌 |
| 카드 결정 | 화면이 본 카드 `version`을 같이 보냄. 그사이 카드가 바뀌었으면 409 |
| 다른 기관·다른 반 자료 | 있는지 없는지도 알리지 않도록 404로 답함(권한 거부는 이력에 남김) |
| CORS 허용 | 웹 배포 주소 + Capacitor 앱(`https://localhost`, `capacitor://localhost`) |

### 1.1 오류 응답 형식 (모든 API 공통)

```json
{
  "error": {
    "code": "CARD_VERSION_CONFLICT",
    "message": "다른 사람이 먼저 카드를 처리했어요. 새로고침해 주세요.",
    "trace_id": "8f2c…",
    "details": { "current_version": 3 }
  }
}
```

| HTTP | `code` 예 | 언제 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 필드 형식이 틀림. `details.fields`에 칸 이름 |
| 401 | `UNAUTHENTICATED` | 토큰 없음·만료·무효 |
| 403 | `FORBIDDEN_ROLE` | 역할상 못 하는 일(예: 학부모가 카드 결정) |
| 404 | `NOT_FOUND` | 없거나, 다른 기관·반 자료 |
| 409 | `CARD_VERSION_CONFLICT` · `SLOT_TAKEN` · `ALREADY_DECIDED` | 동시 처리·예약 겹침·이미 결정됨 |
| 422 | `NEEDS_INFO` | 필수 정보가 빠짐. `details.missing_fields`에 물어볼 항목 |
| 503 | `UPSTREAM_UNAVAILABLE` | 모델·외부 API 장애. 요청은 저장되고 나중에 다시 처리 |

`message`는 화면에 그대로 띄울 수 있는 한국어 문장으로 쓴다. `trace_id`는 이력·LangSmith에서 같은 호출을 찾는 값이다.

## 2. 화면 ↔ 백엔드

### 2.1 학부모

| 하는 일 | 보냄 | 받음 | 권한 |
| --- | --- | --- | --- |
| 로그인 | `login_id`, `password` | `access_token`, `user { id, role, display_name, org_id }`, `children[]` | 전체 |
| 요청 만들기 | `client_request_id`, `type`, `body`, `child_id` | `request { id, status, missing_fields[] }` | 학부모 |
| 내 요청 목록 | `status`(선택) | `items[] { id, type, title, status, status_label, updated_at, next_action }` | 자기 요청만 |
| 요청 상세 | — | `request`, `messages[]`, `timeline[] { action, at, by }`, `consultation?` | 자기 요청만 |
| 대화 이어 쓰기 | `body` | `message { id, sender_type, body, created_at }` | 자기 요청만 |
| AI 진행 보기(스트리밍) | — | SSE 이벤트(3장) | 자기 요청만 |
| 상담 후보 고르기 | `slot_id` | `slot { id, status: "chosen_by_parent" }` | 자기 요청만 |
| 알림 목록·읽음 | `notification_id` | `items[] { id, kind, title, body, request_id, read_at }` | 자기 알림만 |

### 2.2 교사·원장

| 하는 일 | 보냄 | 받음 | 권한 |
| --- | --- | --- | --- |
| 받은함 | `status`, `kind`, `assignee=me`(선택) | `items[] { id, kind, status, request_type, title, urgency, assignee, due_at, is_delayed }` | 교사: 담당 반·자기 카드 / 원장: 원 전체 |
| 카드 상세 | — | `card { id, kind, status, version, draft, check_result, check_attempts }`, `evidence[] { document_title, location, effective_from, quote }`, `request`, `timeline[]` | 같음 |
| 카드 결정 | `version`, `decision`(`approve`·`edit_approve`·`reject`·`hold`), `reason_code`, `reason_text`, `edited_content` | `card { status, version }`, 다음 카드가 생기면 `next_card_id` | 담당 교사·원장 |
| 상담 확정 | `version`, `slot_id` | `booking { id, room, period }` 또는 409 `SLOT_TAKEN` | 담임 |
| 규칙 제안 결정 | `rule_id`, `decision`(`activate`·`decline`) | `rule { id, status }` | 규칙 주인 |
| 원장 보고 지시·재배정 | `card_id`, `assignee_id`, `reason` | `card { assignee, version }` | 원장 |
| 원장 현황 | — | `unassigned`, `waiting`, `delayed`, `done_today`, `reassignments[] { card_id, from, to, reason, at }`, `eval[] { suite, requested_model, returned_model, passed, total, started_at }` | 원장 |
| 알림장 초안 | `classroom_id`, `note_date`, `activities`, `supplies` | `notes[] { child_id, status, content, open_checks[] }` | 담임 |
| 알림장 보내기 | `note_ids[]` | `sent[]`, `blocked[] { note_id, open_checks[] }` | 담임 |
| 자료 올리기 | 파일, `doc_type`, `visibility`, `classroom_id?`, `effective_from` | `document { id, status, conflicts[] }` | 원장·담임 |

## 3. AI 진행 스트리밍 (SSE)

| 항목 | 안 |
| --- | --- |
| 경로 예 | `GET /requests/{id}/stream` |
| 읽는 법 | 토큰을 헤더로 보내야 하므로 브라우저 `EventSource` 대신 `fetch` 스트림으로 읽음 |
| 이벤트 | `stage`(단계 바뀜) · `token`(답변 글자) · `card`(카드가 생김) · `done`(끝) · `error`(오류, 1.1과 같은 형식) |

```text
event: stage
data: {"stage": "classified", "label": "요청을 분류했어요", "at": "2026-12-01T10:00:02+09:00"}

event: token
data: {"text": "12월 체험학습은 "}

event: card
data: {"card_id": "…", "kind": "reply_draft", "status": "pending"}

event: done
data: {"request_status": "awaiting_review"}
```

`stage` 값은 요청 상태(`received`→`classified`→…)와 같은 이름을 쓴다(NFR-10).

## 4. 백엔드 ↔ 에이전트 (Function Calling 도구)

에이전트는 기관이 고정된 서비스 권한으로 도구를 부른다. 도구는 DB를 직접 열지 않고 백엔드 함수를 거친다. 모든 도구 호출은 `events`에 `tool_called` 또는 `tool_failed`로 남는다.

| 도구 | 부르는 AI | 받는 값 | 돌려주는 값 |
| --- | --- | --- | --- |
| `route_request` | 감독 | `request_id` | — (아래 분류 결과를 저장) |
| `create_card` | 감독·자료 | `request_id`, `kind`, `assignee_role`, `draft`, `evidence[]` | `card_id` |
| `notify_staff` | 감독 | `card_id`, `reason` | `notification_id` |
| `search_documents` | 자료 | `query`, `classroom_id?`, `doc_types[]?`, `top_k` | `chunks[] { chunk_id, document_title, location, effective_from, content, score }` |
| `get_law_article` | 자료 | `law_name`, `article` | `text`, `source_url`, `fetched_at` |
| `get_memory` | 기억 | `owner_id`, `kinds[]` | `memories[] { kind, reason_code, content, structured }`, `active_rules[]` |
| `propose_rule` | 기억 | `owner_id`, `reason_code`, `rule_text`, `rule_json` | `rule_id` 또는 이미 있으면 기존 `rule_id` |
| `check_draft` | 검사 | `card_id` | — (아래 검사 결과를 저장) |
| `return_to_step` | 검사 | `card_id`, `step`, `issues[]` | `attempt`(1·2). 3번째면 오류 대신 사람 카드로 넘김 |
| `find_consult_slots` | 코드 | `request_id`, `teacher_id`, `from`, `to`, `rules[]` | `slots[] { slot_id, period, room, rank }` (최대 3개) |
| `book_slot` | 코드 | `slot_id`, `confirmed_by` | `booking_id` 또는 `SLOT_TAKEN` |

### 4.1 에이전트가 내는 결과 형식

| 결과 | 필드 |
| --- | --- |
| 분류(감독 AI) | `type`, `urgency`(`low`·`normal`·`high`·`urgent`), `topic_key`, `assignee_role`, `missing_fields[]`, `handoff_reason?`(모호·긴급·고위험이면 사람에게 바로) |
| 답변 초안(자료 AI) | `text`, `evidence[] { chunk_id, quote }`, `no_evidence`(근거 없음이면 참), `conflict`(문서 충돌이면 참) |
| 검사(검사 AI) | `passed`, `issues[] { field, problem }`(출처·날짜·대상·누락·민감정보), `attempt` |

## 6. 회의에서 정할 것

1. 1.1 오류 `code` 목록과 화면 문구를 누가 쓰는지
2. 거절 이유 코드(`reason_code`) 목록
3. "같은 내용 3번째 민원"을 셀 기간(제안: 30일)과 `topic_key` 만드는 기준
4. 카드 종류별 처리 기한(`due_at`). 원장 현황의 '지연' 기준
5. SSE `stage` 문구를 화면이 쓸지 서버가 보낼지
6. 학부모가 상담 후보를 고른 뒤 담임 확정까지 후보를 잡아 둘 시간
7. 4장 도구 이름(기획서 6장의 예시 이름)을 이대로 확정할지
