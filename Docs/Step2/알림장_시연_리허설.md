# 알림장 시연 리허설 순서표

중간 발표(12/08) 시연에서 담임이 알림장을 만들어 반 전체에 보내는 장면을 미리 돌려 보는 순서표다. 데이터와 날짜 규칙은 시연과 똑같이 맞춘다. 화면 리허설은 이 표를 보면서 웹에서 하고, 백엔드에는 같은 순서를 API로 끝까지 돌리는 스크립트 `tools/rehearse_daily_note.py`를 둔다. 데이터와 규칙의 기준은 [알림장 에이전트 흐름](알림장_에이전트_흐름.md) 10장(시연 기준 v1)이고, 상태 이름은 [T04](유치온_T04_흐름권한명세.md) 6.1과 [T25](../Step3/T25_단일에이전트_상태전이_설계서.md) 2.1에 적힌 이름을 그대로 쓴다.

## 1. 리허설 기준

| 항목 | 기준 |
| --- | --- |
| 반·계정 | 만 4세 별빛반 20명, 담임 `teacher01`, 학부모 `parent01`(하늘 보호자). 비밀번호는 가상 원 시드 값 |
| 날짜 | 실행한 날(한국 시각). 시드의 `--refresh-note-requests`가 가장 늦은 요청 날짜(11/20)를 오늘로 옮기므로, 어느 날 돌려도 11/20 요청이 그날 요청이 된다 |
| 반 활동·준비물 | `class_days.json`의 11/20 값 |
| 아이 메모 | `child_memos.json`의 11/20 값 17개. 메모가 빈 3명은 보내지 않는다(화면도 같다) |
| 오늘 보호자 요청 | 5개: 하늘 문의, 노을 귀가, 지아 투약(GR-02), 한결 귀가(GR-10), 아라 문의(GR-19). 초안에는 투약·귀가 3개만 들어가고 문의 2개는 받은함에서만 다룬다 |
| 발송이 막히는 아이 | 지아(2장) |
| 고쳐 보는 아이 | 하늘. 아이 메모 줄을 "기침을 가끔 했지만 열은 없었고 낮잠도 잘 잤어요."로 고친다. 학부모 화면 시연 계정의 아이라 마지막에 학부모 쪽에서 확인한다 |

## 2. 지아에게 확인 항목이 남는 이유

막히는 장면에 쓸 아이로는 코드 규칙에 늘 걸리는 아이를 골랐다. 모델 판단에 맡기면 그 장면이 안 나올 수도 있어서다. 그래프의 코드 검사(`agents/graphs/daily_note.py`의 `code_checks()`)는 그날 투약 요청이 있는 아이에게 늘 `sensitive` 확인 항목(`item_key: medication`, `request_id` 포함)을 남긴다. 자료 AI가 그 요청을 초안에 옮기지 못했다면 대신 `request_missed`가 남는다. 어느 쪽이 되든 지아의 알림장은 `needs_check`가 된다. 기본 작성기인 대역도 메모에 있는 '약'을 보고 `sensitive`를 남기니, 작성기가 무엇이든 지아에게는 확인 항목이 남는다.

지안도 코드 검사에 늘 걸린다. 메모에 다른 아이 이름('지아')이 들어 있어서 `other_child`가 남기 때문이다. 이 리허설에서는 지안을 먼저 해결하는 아이로 쓴다. 이 밖의 아이에게 붙는 항목은 모델이 판단하는 것이라 달라질 수 있다. 스크립트는 이런 항목도 담임이 하듯 해결한 뒤 확인한다.

| 작성기 | 초안 직후 확인 항목이 있는 아이 | 반 발송 시도에서 막힌 아이 |
| --- | --- | --- |
| 대역(`stub_writer`), 2회 | 하늘 `date_check`·`sensitive`, 노을 `request_missed`, 지아 `sensitive` | 지아 |
| 실제 그래프(`graph`, gpt-6-luna), 2회 | 아라 `sensitive`, 지아 `sensitive` 2개, 지안 `other_child` | 지아 |

실제 그래프로 돌렸을 때 지아에게는 `sensitive`가 2개 붙었다. 하나는 코드 규칙이 남긴 투약 확인이다. 나머지 하나는 모델 결과에 따라 붙는 항목이라 개수가 달라질 수 있다. 두 항목은 서로 다른 줄에 붙어 있어서, 같은 줄의 확인을 하나로 합치는 규칙을 적용해도 합쳐지지 않는다.

## 3. 순서표

화면 경로는 [T12](유치온_T12_화면지도.md)에 나온 경로를 따르고, 괄호 안에는 웹 코드에 적힌 목업 번호를 적었다. 상태 칸에는 세 가지 상태가 섞여 있다. `queued`…`failed`는 초안 작업(`daily_note_inputs.draft_status`)의 상태다. `draft`…`sent`는 아이별 알림장(`daily_notes.status`)의 상태이고, `pending`·`done`은 반 확인 카드(`cards.status`)의 상태다.

| # | 화면에서 누르는 것 | 부르는 API | 바뀌는 상태 | 화면에 보여야 할 것 |
| :---: | --- | --- | --- | --- |
| 1 | `teacher01`로 로그인 → 홈 → 오늘 알림장 `/teacher/notes`(A-03) | `POST /auth/login`, `GET /classrooms/{반}/children`, `GET /daily-notes` | — | "오늘 알림장 만들기", 관찰 기록 반영 인원 |
| 2 | 오늘 함께한 활동·가정에서 준비할 것을 적고 **아이별 초안 만들기** | `POST /daily-notes/drafts` → 202 | 작업 `queued`, 카드 `pending` | 만드는 중 화면(A-04) |
| 3 | 기다린다 | `GET /daily-notes/drafts/{input_id}`를 0.8초마다 | `queued` → `running` → `succeeded` | 단계 표시. 실패면 "초안을 만들지 못했어요"와 다시 만들기 |
| 4 | 알림장 확인 화면(A-05)을 본다 | `GET /daily-notes` | 아이마다 `draft` 또는 `needs_check` | '먼저 확인할 아이'에 지아가 있다 |
| 5 | 하늘 `/teacher/notes/:noteId` → 아이 메모 줄 **고치기** → 저장(다른 줄 항목이 남으면 그 항목 버튼으로 해결) → **확인하기** | `PATCH /daily-notes/{id}`(`content`, `resolved_checks`) → `PATCH`(`confirm`) | `needs_check` 또는 `draft` → `draft` → `ready` | 하늘이 '확인함'으로 옮겨 간다 |
| 6 | 지아를 뺀 걸린 아이는 상세에서 해결·확인하고, '반 활동만 작성된 아이'는 **모두 문제 없음으로 옮기기**, 그다음 **N명 모두 확인** | `PATCH /daily-notes/{id}` | `ready` | 확인 필요 1명(지아)만 남는다 |
| 7 | 발송 막힘(4장) | `POST /daily-notes/send` → 409 | 바뀌지 않음 | 보내기 버튼이 잠겨 있다 |
| 8 | 지아 상세 → 확인 항목의 **보내도 되는 내용이에요** → **확인하기** | `PATCH`(`resolved_checks`) → `PATCH`(`confirm`) | `needs_check` → `draft` → `ready` | 확인을 누르기 전까지는 잠겨 있고, 누르면 "20명 모두 확인했어요" |
| 9 | **20명에게 한 번에 보내기** → 시트(A-07)의 **보내기** | `POST /daily-notes/send` → 200 `sent_count: 20` | 20명 `sent`, 카드 `done`, 학부모에게 `note_sent` 알림 | "20가정에 알림장을 보냈어요" |
| 10 | `parent01`로 로그인 → 학부모 홈 `/parent/home` → 알림 `/parent/notifications` | `GET /daily-notes?date=`, `GET /notifications` | — | 하늘 알림장에 5번에서 고친 문장이 보이고, 알림 목록에 '오늘 알림장'이 1건 있다 |

## 4. 발송이 막히는 장면

지아 한 명만 확인하지 않은 채로 반 보내기를 부르면 서버는 409 `NOTE_BATCH_BLOCKED`로 답한다. 이때 `details.blocked`에는 지아 한 명과 아직 남은 확인 항목이 담긴다. 반 전체를 한 트랜잭션에서 확인하기 때문에 나머지 19명의 알림장도 나가지 않는다. 지아의 상태는 T04 6.1에 정한 전이대로 바뀐다.

| 지아 상태 | 반 보내기 | 근거 |
| --- | --- | --- |
| `needs_check`(항목 남음) | 409, `blocked`에 지아와 `open_checks` | 리허설 스크립트 7단계 |
| `draft`(항목 해결, 확인 전) | 409, `blocked`에 지아, `open_checks`는 빈 목록 | 리허설 스크립트 8단계 |
| `ready` | 200, `sent_count: 20` | 리허설 스크립트 9단계 |

화면 리허설에서 보게 될 장면은 잠긴 보내기 버튼, 그리고 '먼저 확인할 아이'에 있는 지아다. 확인하지 않은 알림장이 있는 동안에는 보내기 버튼이 잠기고, 버튼 위에 자물쇠와 함께 "아직 확인 안 한 알림장 1개"가 보이기 때문이다(`apps/web/src/features/notes/NotesPage.tsx`의 보내기 칸 `Dock` 안내). 화면 목록이 오래된 상태에서 보내다가 409를 받으면, 화면에 "보내기가 막혔어요"가 뜨고 막힌 아이 이름과 문제 문장도 함께 나온다(같은 파일의 `blocked` 안내 칸). 409 응답이 제대로 오는지는 스크립트로 확인한다.

## 5. 시연 날 아침에 할 일

1. 보호자 요청 날짜를 오늘로 옮긴다. 팀 서버에서 `docker compose -p yuchion-server exec -T api python -m db.seeds.demo --refresh-note-requests`를 실행하면 된다. 11/24에 팀 서버를 읽기만 해서, 이 프로젝트·서비스 이름으로 명령이 들어가는지와 컨테이너 코드에 이 옵션이 있는지 확인했다. 명령 자체는 실행하지 않았다.
2. `docker compose -p yuchion-server exec -T api env`로 환경 변수를 열어, 작성기가 `DAILY_NOTE_WRITER=graph`이고 실행 위치가 `RUN_IN=worker`인지 본다.
3. 시연 당일에는 팀 서버에서 리허설 스크립트를 돌리지 않는다. 스크립트는 그날 반 알림장을 실제로 만들어서 보낸다. 그래서 같은 날 시연에서 같은 반·날짜로 초안을 만들면 새 초안이 생기지 않고, 이미 보낸 작업이 돌아온다. 팀 서버 리허설은 전날까지 끝낸다. 다음 날 아침에 1번을 하면 그날은 다시 빈 날짜가 된다.

## 6. 자동 리허설 스크립트

스크립트는 `PYTHONPATH=. python tools/rehearse_daily_note.py --base-url <API 주소>`로 돌린다. 기본 대상은 로컬(`http://localhost:8000`)이다. 팀 서버에서 돌리려면 그 접속 주소와 함께 `--remote-ok`를 붙여야 한다. 그날 알림장을 실제로 보내는 일이라, 이 옵션이 없으면 로컬이 아닌 주소에서는 시작하지 않는다. `--dry-run`을 붙이면 서버에는 아무것도 보내지 않고, 위 10단계에서 부를 API만 보여 준다. 실행하면 단계마다 응답 코드와 상태가 한 줄씩 나온다. 이 줄에는 ID와 시각이 없어서 두 번 돌린 출력을 그대로 비교할 수 있다. 같은 반·날짜 작업이 이미 있거나, 지아에게 확인 항목이 없거나, 지아 말고 다른 아이도 막히면 스크립트는 그 자리에서 멈추고 1로 끝난다.

## 7. 실행 범위와 결과

기준 커밋은 develop `ab58b7c`다. 로컬에서는 임시 PG에 마이그레이션과 데모 시드를 넣고 날짜를 옮긴 다음, API를 DB 모드(`RUN_IN=api`)로 띄워서 돌렸다.

| 실행 | 실제인 것 · 모의인 것 | 결과 |
| --- | --- | --- |
| 로컬 · 대역 작성기, 2회 | DB·API는 실제, 작성기는 대역 | 10단계 모두 통과. 걸린 시간 줄을 빼면 두 출력이 같다 |
| 로컬 · 실제 그래프(gpt-6-luna), 2회 | 모델까지 실제, 워커 대신 API 백그라운드 실행 | 초안 작업 26초와 14초. 두 번 다 지아만 막히고 20명 발송 |
| 시험 `tests/integration/db/test_rehearse_daily_note.py` | DB 실제, 작성기는 대역 / 가짜 모델을 붙인 그래프 | 2개 통과. 검사 AI가 아무것도 짚지 않아도 지아에게서 막힌다 |
| 팀 서버 | 돌리지 않음 | 실제 연동 대기 |
| 웹 화면 리허설 | 성주님 | 대기 |

남은 일은 두 가지다. 화면 리허설 때 메모 17개를 담임 화면 '오늘 기록'에 넣는 방법(브라우저 저장)은 웹 쪽과 함께 정한다. 그리고 팀 서버의 식단 문서는 이번에 확인하지 못했다. 로컬에서 나온 식사 줄은 데모 시드의 가상 식단표에서 가져온 것이다.
