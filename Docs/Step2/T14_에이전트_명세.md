도구 이름·인자·돌려주는 값은 계약표 4장이 기준이다. 이 문서는 그 도구를 **어느 에이전트가, 어떤 입력을 받아, 무엇을 내고, 언제 사람에게 넘기는지**를 역할별로 묶는다. 도구 인자를 여기서 새로 정하지 않는다.

## 1. 에이전트 한눈에 보기

| 에이전트 | 하는 일 | 쓰는 도구(계약표 4장) | 내는 결과(계약표 4.1) | 사람에게 넘기는 기준 |
| --- | --- | --- | --- | --- |
| 감독 AI | 요청 유형·긴급도·주제·위험 등급 분류, 다음 단계 선택, 카드·알림 만들기 | `route_request` · `create_card` · `notify_staff` · `request_consultation` · `get_my_requests` · `get_daily_note` · `find_saved_answer` | 분류 결과 | 정보 부족·모호·긴급·판단 필요·반복 3번째·권한 밖 |
| 자료 AI | 원 자료·법령에서 근거를 찾아 답변 초안 쓰기, 반 활동·아이별 메모·보호자 요청으로 알림장 초안 쓰기 | `search_documents` · `get_law_article` · `create_card`(초안 카드). 알림장은 도구 없음(입력을 백엔드가 줌) | 답변 초안 · 알림장 `content.items[]` | 근거 없음·문서 충돌 · 판단이 서지 않는 메모는 `child` 줄을 비움 |
| 기억 AI | 담임별 거절 이유·선호·말투를 불러와 다음 제안에 넘기기, 같은 이유 3번이면 규칙 제안 | `get_memory` · `propose_rule` | 기억 묶음(`memories[]`·`active_rules[]`) | 규칙은 담임 승인 전 적용 안 함, 민감·일회성 정보는 저장 안 함 |
| 검사 AI | 내보내기 전 출처·날짜·대상·누락·민감정보 대조, 알림장은 메모와 대조, 실패하면 앞 단계로 돌려보내기 | `check_draft` · `return_to_step` | 검사 결과 · 알림장 `open_checks[]` | 2번 돌려보내도 실패(3번째) |
| 코드(에이전트 아님) | 상담 빈 시간 계산, 예약 저장·충돌 검사 | `find_consult_slots` · `book_slot` | 상담 후보 `slots[]` · `booking_id` | 규칙대로 실행. 후보가 없으면 감독 AI에 돌려줌 |

사진 AI는 최종 단계 선택 기능이라 T14 범위에서 뺀다(기획서 6장).

## 2. 흐름별로 누가 언제 일하나

| 흐름 | 순서 | 사람이 하는 일 |
| --- | --- | --- |
| 안내 문의 | 감독(분류, `find_saved_answer`로 원에 남은 답 확인) → 남은 답이 없거나 최신이 아니면 기억(담임 말투) → 자료(근거 검색·초안) → 검사 → 담임 카드 | 담임이 초안 승인 후 회신 |
| 상담 | 감독(분류) → 기억(담임 상담 규칙) → 코드(`find_consult_slots`, 후보 최대 3개) → 학부모 선택(`request_consultation` 또는 화면) → 담임 카드 | 담임이 학부모가 고른 후보 중 하나를 확정(`book_slot`) |
| 민원 일반 | 감독(분류·주제·반복 수) → 기억(담임 말투) → 자료(근거·초안) → 검사 → 담임 카드. 반복 3번째면 원장 보고 카드도 만들고 담임 카드는 유지 | 담임 회신 승인 → 학부모 확인 → 담임 처리 완료 |
| 민원 긴급·판단 필요 | 감독(분류) → **초안 없이** 담임·원장 카드를 함께 만들고 `notify_staff` | 담임·원장이 직접 판단. 원장은 보고 확인·지시 |
| 정보 부족 | 감독(분류, `missing_fields[]`) → 요청 상태 `needs_info`, 정보 요청 카드 | 학부모가 빠진 정보를 채움 |
| 상태 조회·알림장 보기 | 감독이 `get_my_requests`·`get_daily_note`로 읽어서 안내(읽기 전용) | 없음 |

근거: 기획서 2.3·FR-03·FR-04·FR-05·FR-07, T04 3.2·합의 1·7, 계약표 6장 ⑧(같은 질문은 MVP에서 묶지 않음).

## 3. 에이전트별 명세

### 3.1 감독 AI (`agents/supervisor`, 모델 설정 `LLM_MODEL_SUPERVISOR`)

| 항목 | 내용 |
| --- | --- |
| 언제 | 학부모 요청이 들어올 때마다 처음, 그리고 다른 단계가 결과를 돌려줄 때(슈퍼바이저 노드) |
| 입력 | 요청 원문(`body`)·화면에서 고른 유형(`type`)·`child_id`·이전 요청(`previous_request_id?`)·대화 메시지. 로그인 정보(기관·반·학부모 ID)는 백엔드가 채우고 모델에게 보이지 않음 |
| 출력 | 분류 결과(계약표 4.1): `type`, `urgency`, `topic_key`(주제 10개 + `other`, 6장 ②), `assignee_role`, `missing_fields[]`, `handoff_reason?`. 민원이면 `risk_level`, `risk_category?`, `risk_confidence`, `repeat_count`. 그리고 다음 단계(자료·코드·사람) |
| 도구 | `route_request`(분류 결과 저장) · `create_card`(카드 만들기, 원장 보고면 `escalate_to_director = true`) · `notify_staff`(긴급·판단 필요 알림) · `request_consultation`(학부모가 고른 상담 시간 남기기) · `get_my_requests`·`get_daily_note`(읽기 전용 조회) · `find_saved_answer`(원에 남은 답 확인) |
| 사람에게 넘김 | ① 필수 정보가 빠짐 → `needs_info` ② 유형이 모호함 → `handoff_reason`, 담임 카드 ③ 민원 긴급·판단 필요 → 초안 없이 담임·원장 카드 + 알림(FR-03) ④ 같은 반·30일·같은 `topic_key` 3번째(`other` 제외) → 원장 보고 카드, 담임 카드 유지(FR-07) ⑤ 권한 밖·범위 밖 질문 → 도구를 부르지 않고 안내(4장) |
| 하지 않는 것 | 회신·완료·상담 확정, 법률 판단, 최종 위험 등급 확정(담임이 다시 분류할 수 있음) |

- 위험 등급: 긴급은 `child_safety`·`staff_attack`·`legal_external`·`privacy_leak` 중 하나를 높은 확신으로 판단한 경우, 확신하지 못하면 `uncertain`(판단 필요). 긴급·판단 필요를 나누는 `risk_confidence` 기준값은 T06 평가로 정한다(기획서 F4, DB 설계서 2.2).
- 원에 남은 답: `similarity`가 기준 이상이고 `sources_current`가 참일 때만 그 답을 담임 카드 초안으로 쓴다. 학부모에게 바로 보내지 않는다(T04 합의 7, 자동 회신 금지).
- 근무 시간 밖 긴급 알림을 언제 보낼지는 서버가 `deliver_after`로 정한다(6장 ⑬). 감독 AI는 `risk_category`만 정확히 붙인다.

### 3.2 자료 AI (`agents/documents`, `LLM_MODEL_DOCUMENT`)

| 항목 | 내용 |
| --- | --- |
| 언제 | 감독 AI가 안내 문의·민원 일반을 넘겼을 때, 그리고 검사 AI가 돌려보냈을 때 |
| 입력 | 질문 원문·감독 AI 분류 결과·기억 AI가 준 담임 말투(`memories[]`)·검사 AI가 돌려보낸 `issues[]`(있으면) |
| 출력 | 답변 초안(계약표 4.1): `text`, `evidence[] { chunk_id, quote }`, `no_evidence`, `conflict` |
| 도구 | `search_documents`(원 자료 검색. 모델은 `kindergarten_id`·`doc_type`·`query`만 채우고 반 범위는 백엔드가 정함) · `get_law_article`(법령 원문) · `create_card`(초안·근거를 붙인 담임 카드) |
| 사람에게 넘김 | ① 근거가 없음(`no_evidence = true`) ② 문서끼리 날짜·숫자가 다름(`conflict = true`) → 둘 다 추측해서 답하지 않고 담임 카드로 넘김(FR-04) |
| 하지 않는 것 | 근거 없는 문장 쓰기, 법률 해석(법령은 원문과 출처만 붙임), 학부모에게 바로 보내기 |

- 초안의 모든 사실 문장에는 근거 문서명·위치·적용일(`document_title`·`location`·`effective_from`)이 붙어야 한다(FR-04). 검사 AI가 이것을 대조한다.

**알림장 초안** (11/20 팀 결정 ① "메모에 없는 말은 쓰지 않는 알림장 AI", 7장 1)

| 항목 | 내용 |
| --- | --- |
| 언제 | 담임이 알림장 초안 만들기(API 22)를 누른 뒤, 아이마다 한 번. 검사 AI가 돌려보내면 그 아이만 다시 |
| 입력 | 백엔드 입구 함수(API 설계 v0.4 3.19): 반 공통 `activities`·`supplies` · 아이별 `{child_id, display_name, memo, requests[{request_id, type, text}]}`(빈 메모는 보내지 않음) · 그날 식단 `menu` · 담임 말투(`memories[]`, 다음 주) · 검사 AI `issues[]` |
| 출력 | 아이별 `content.items[] {key, label, value, source}` — `day`(반 활동) · `child`(메모를 풀어 쓴 문장, 메모가 비면 없음) · `medication`·`pickup`·`inquiry`(보호자 요청마다 한 줄, 출처 `request`, 계약 v0.4.1) · `supplies` · `meal`(입력 `menu` 근거). 키는 API 설계 v0.4 3.7 |
| 도구 | 없음. 식단은 백엔드가 `menu`로 넣고, 저장·카드·상태는 백엔드가 함 |
| 규칙 | 메모에 없는 사실·이유·평가를 더하지 않음. 반 공통 활동을 그 아이가 했다고 쓰지 않음. 다른 아이 이름·가정사·선생님 혼자 보는 메모는 옮기지 않음. 자세한 규칙은 [`agents/prompts/documents.md`](../../agents/prompts/documents.md) '알림장 초안 쓰기' |
| 평가 | 함정 20문항 [`data/evaluation/daily_note/`](../../data/evaluation/daily_note/README.md)(PR #262) |

### 3.3 기억 AI (`agents/memory`, `LLM_MODEL_MEMORY`)

| 항목 | 내용 |
| --- | --- |
| 언제 | 자료 AI 초안이나 코드의 상담 후보를 만들기 전, 그리고 담임이 카드를 거절·반려한 뒤 |
| 입력 | 담당 담임 ID(`owner_id`)·필요한 기억 종류(`kinds[]`)·거절 이유(`reason_code`, 6장 ① 8개) |
| 출력 | `memories[] { kind, reason_code, content, structured }`, `active_rules[]` → 자료 AI(말투)·코드(상담 규칙 `rules[]`)로 넘김 |
| 도구 | `get_memory`(기억·적용 중인 규칙 불러오기) · `propose_rule`(같은 사람에게 같은 `reason_code`가 3번 쌓이면 규칙 제안. 이미 있으면 기존 `rule_id`) |
| 사람에게 넘김 | 규칙 제안은 `rule_proposal` 카드로 담임에게 가고, 담임이 `activate`해야 적용된다(FR-06) |
| 하지 않는 것 | 아이 건강·가정사 같은 민감 정보나 한 번만 쓸 정보 저장, 담임 승인 없이 규칙 적용 |

- 상담 거절은 `slot_unavailable`·`room_unavailable` 코드로 남아야 규칙이 생긴다(DB 설계서 2.2).

### 3.4 검사 AI (`agents/reviewer`, `LLM_MODEL_CHECKER`)

| 항목 | 내용 |
| --- | --- |
| 언제 | 자료 AI 초안이 담임 카드에 올라가기 전, 아이별 알림장이 담임 확인 전 |
| 입력 | 카드(`card_id`: 초안·근거) 또는 알림장(`note_id`) |
| 출력 | 검사 결과(계약표 4.1): `passed`, `issues[] { field, problem }`, `attempt` |
| 도구 | `check_draft`(출처·날짜·대상·누락·민감정보 대조, 알림장이면 `open_checks` 저장) · `return_to_step`(앞 단계로 돌려보냄, `attempt` 1·2) |
| 사람에게 넘김 | 2번 돌려보내도 통과하지 못하면(3번째) 오류로 끝내지 않고 사람 카드로 넘김(FR-08) |
| 하지 않는 것 | 초안을 직접 고쳐 쓰기(쓴 AI와 검사 AI를 나눔, NFR-03) |

| 검사 항목 | 보는 것 |
| --- | --- |
| 출처 | 사실 문장마다 `evidence[]`가 있고, 인용(`quote`)이 그 조각에 실제로 있는가 |
| 날짜 | 근거 문서의 `effective_from`이 질문한 날짜에 맞는가, 더 새 판이 있지 않은가 |
| 대상 | 다른 반 대상 자료를 쓰지 않았는가 |
| 누락 | 질문한 것에 모두 답했는가 |
| 민감정보 | 다른 아이·다른 가정 정보, 전화번호 같은 개인정보가 들어 있지 않은가 |

알림장은 출처 대신 **메모와 대조**하고, 결과를 `open_checks[] {id, item_key, kind, problem, sentence, request_id?}`로 남긴다(API 설계 v0.4 3.7). `kind`는 아래 8값, `problem`은 선생님이 읽는 설명, `sentence`는 걸린 초안 문장이다.

| `kind` | 이럴 때 | 처리 |
| --- | --- | --- |
| `not_in_memo` | 메모·반 공통·식단 어디에도 없는 말, 반 활동을 그 아이가 했다고 씀 | 자료 AI로 돌려보냄(최대 2번), 그래도 남으면 `open_checks` |
| `sensitive` | 다침·열·투약·친구 갈등·부정적 행동·가정사·선생님 혼자 보는 메모 | 돌려보내지 않고 `open_checks`(선생님이 꼭 봄) |
| `other_child` | 다른 아이 이름이 있거나 메모가 다른 아이 이야기로 보임 | `open_checks` |
| `date_check` | 메모 날짜가 준비물·통신문 날짜와 다름 | `open_checks` |
| `absent` | 결석 메모 | `open_checks`(보낼지 선생님이 정함) |
| `draft_failed` | 자료 AI 쓰기가 다시 해도 실패 | 그 아이만 `child` 줄 없이 저장 + `open_checks` |
| `check_failed` | 검사가 다시 해도 실패 | 통과로 보지 않고 `open_checks` |
| `request_missed` | 그날 보호자 요청을 다룬 줄이 없음 | 자료 AI로 돌려보냄(최대 2번), 그래도 남으면 `open_checks`(`request_id`) |

`open_checks`가 남은 아이가 있으면 반 전체 발송이 막힌다(409 `NOTE_BATCH_BLOCKED`, API 26).

## 6. 도구가 실패했을 때 (계약표 6장 ④)

실패 코드와 `retryable` 값, 실패 후 처리 기본값은 T13 API 설계 문서 v0.2(PR #256) 5.2·5.4가 정했다. 이 장은 그 기본값 위에서 **에이전트가 실제로 무엇을 하고, 학부모 앞이면 무엇이라고 말하는지**를 정한다. 학부모에게 하는 말은 팀 자체 30문항 YC-F01~F04의 기대 동작과 같다.

### 6.1 공통 순서

1. 도구 결과의 `ok`가 거짓이면 `error.retryable`을 본다.
2. `retryable`이 참이면 **같은 인자로 1번만** 다시 부른다. 거짓이면 다시 부르지 않는다.
3. 그래도 실패하면 6.2 표의 '그래도 실패하면'대로 한다.
4. 실패를 숨기지 않는다. 결과를 지어내지 않는다. 실패했는데 "선생님께 전달했어요", "처리됐어요", "예약됐어요"라고 말하지 않는다(YC-F04).
5. 요청 하나의 AI 처리가 전체 3분을 넘으면 멈추고 초안 없는 사람 카드로 넘긴다(T13 6.1, `handoff_reason = ai_timeout`).

모델 호출 자체의 재시도(최대 2번)와 `tool_failed` 기록은 서버가 하므로 에이전트가 따로 하지 않는다(T13 6.2, 5.2).

### 6.2 도구별 행동

| 도구 | 다시 부르는 실패 | 그래도 실패하면 에이전트 행동 | 학부모에게 하는 말(학부모 대화 중일 때) |
| --- | --- | --- | --- |
| `route_request` | `UPSTREAM_UNAVAILABLE`·`SAVE_FAILED` | 분류 없이 담당 없는 사람 카드(받은함 '미배정')로 넘김 | "요청은 받았어요. 선생님이 직접 확인한 뒤 알려 드릴게요." |
| `create_card` | `SAVE_FAILED` | 더 진행하지 않고 학부모 안내까지만 함. 요청은 `POST /requests` 때 이미 저장돼 학부모 '내 요청' 화면에는 '접수됨'으로 보이고, 카드 없이 5분 넘은 요청은 서버 점검 작업이 받은함 '미배정' 카드로 다시 올림(T13 5.4·6.3) | "말씀하신 내용은 받았는데 선생님께 넘기는 중에 저장 오류가 났어요. 확인이 늦어질 수 있으니 급하시면 원으로 전화 주세요." "선생님께 전달했어요"·"처리됐어요"라고 하지 않음 (YC-F04) |
| `notify_staff` | `SAVE_FAILED` | 카드는 받은함에 남으므로 진행. 긴급·판단 필요 카드면 `warnings[]`에 `notify_failed`를 붙여 받은함에서 눈에 띄게 함(T13 3.7·5.4) | 없음(교직원 쪽 일) |
| `search_documents` | `TOOL_TIMEOUT`·`UPSTREAM_UNAVAILABLE` | 추측하지 않고 `no_evidence = true`로 담임 카드 | 학부모에게 바로 답하지 않음. 담임이 확인한다고만 안내 |
| `get_law_article` | `UPSTREAM_UNAVAILABLE` | 법령 인용 없이 초안을 쓰고 카드에 '법령 확인 못 함' 표시 | 없음 |
| `get_memory` | `SAVE_FAILED` | 기억 없이 진행(기본 말투·규칙 없음) | 없음 |
| `propose_rule` | `SAVE_FAILED` | 이번엔 제안하지 않음. 다음 거절 때 다시 셈 | 없음 |
| `check_draft` | `TOOL_TIMEOUT`·`UPSTREAM_UNAVAILABLE` | 검사 없이 내보내지 않음. 카드에 '검사 못 함' 표시하고 사람 카드 | 없음 |
| `return_to_step` | 없음(3번째는 `INVALID_TRANSITION`) | 3번째는 오류로 끝내지 않고 사람 카드(FR-08) | 없음 |
| `find_consult_slots` | `TOOL_TIMEOUT`·`SAVE_FAILED` | 시간을 지어내지 않고 멈춤. 빈 목록(`slots = []`)이면 실패가 아니라 그날 빈 시간이 없는 것 | 실패: "지금 상담 가능 시간을 확인할 수 없어요. 잠시 뒤 다시 해 주시거나 담임 선생님께 문의해 주세요." (YC-F01) · 빈 목록: "그날은 가능한 시간이 없어요. 다른 날짜를 알려 주시겠어요?" — 카드는 만들지 않음 (YC-F02) |
| `request_consultation` | `SAVE_FAILED` | 상담 요청이 안 남았다고 보고 진행하지 않음 | "고르신 시간이 저장되지 않았어요. 화면에서 다시 골라 주세요." |
| `book_slot` | 에이전트가 부르지 않음 | 담임 확정 API가 409를 담임 화면에 그대로 보여 줌(T13 5.4) | 없음 |
| `get_my_requests` | `SAVE_FAILED` | 상태를 지어내지 않음 | "지금 진행 상황을 불러오지 못했어요. '내 요청' 화면에서 확인해 주세요." |
| `get_daily_note` | 없음(`NOT_FOUND`) | 알림장이 없으면 실패가 아니라 아직 안 보낸 것 | "그날 알림장은 아직 보내지 않았어요." |
| `find_saved_answer` | `TOOL_TIMEOUT` | 원에 남은 답 없이 평소대로(자료 AI) 처리 | 없음 |

`NOT_FOUND`·`VALIDATION_FAILED`·`FORBIDDEN_SCOPE`·`INVALID_TRANSITION`처럼 `retryable`이 거짓인 실패는 다시 부르지 않고 위 표의 '그래도 실패하면'으로 바로 간다. 다른 기관·다른 가정 자료라서 생긴 `NOT_FOUND`는 "볼 수 없어요"로만 안내하고, 있는지 없는지 말하지 않는다(계약표 1.2).

### 6.3 상담 시간 조회가 시간 초과됐을 때 (FB-016-4)

`find_consult_slots`가 30초 안에 끝나지 않으면 서버가 `TOOL_TIMEOUT`(`retryable` 참)을 돌려준다(T13 5.2·6.1).

| 순서 | 무엇을 하나 | 누가 |
| --- | --- | --- |
| 1 | `TOOL_TIMEOUT`을 받으면 **같은 인자(`teacher_id`·`date`)로 1번만** 다시 부른다. 날짜나 담임을 바꿔 부르지 않는다 | 에이전트 |
| 2 | 다시 불러서 성공하면 평소처럼 후보(최대 3개)를 보여 준다. 학부모에게 실패가 있었다고 말하지 않는다 | 에이전트 |
| 3 | 또 실패하면 더 부르지 않는다. 시간을 지어내지 않고, `request_consultation`도 부르지 않는다 | 에이전트 |
| 4 | 학부모에게 "지금 상담 가능 시간을 확인할 수 없어요. 잠시 뒤 다시 해 주시거나 담임 선생님께 문의해 주세요."라고 안내한다(YC-F01) | 에이전트 |
| 5 | 두 번 모두 `tool_failed`로 `events`에 남긴다. 요청은 이미 저장돼 있으므로 버리지 않는다 | 서버 |

- 두 번 불러도 최대 60초라 요청 하나의 AI 처리 한도 3분(6.1 ⑤) 안에 든다. 3분을 넘기면 6.1 ⑤대로 사람 카드로 넘긴다.
- 빈 목록(`slots = []`)은 시간 초과가 아니다. 다시 부르지 않고 다른 날짜를 묻는다(YC-F02).
- 시간 초과 판정과 기록은 서버가 하고, 에이전트는 받은 `retryable`만 보고 움직인다. 기다리는 간격은 따로 두지 않는다(모델 호출 재시도의 1초·2초 백오프는 서버 몫, T13 6.2).

### 6.4 단계별로 부를 수 있는 도구 (FB-016-4)

T13 5.3 ①과 같다. 허용되지 않은 도구를 부르면 서버가 `FORBIDDEN_SCOPE`(`retryable` 거짓)로 막고, 에이전트는 다시 부르지 않는다.

| 단계 | 에이전트 | 부를 수 있는 도구 | 부를 수 없는 도구 |
| --- | --- | --- | --- |
| STEP 3 단일 에이전트 (T29) | 에이전트 하나(`common.md` + `supervisor.md`) | `book_slot`을 뺀 14개 모두 | `book_slot`(담임의 '상담 확정' API에서만) |

| | 기억 AI | `get_memory` · `propose_rule` | 그 밖의 도구 |
| | 검사 AI | `check_draft` · `return_to_step` | 그 밖의 도구 |
| | 코드(그래프) | `find_consult_slots` | — |
| 모든 단계 | 사람(담임 API) | `book_slot` | 에이전트는 어느 단계에서도 부르지 않음 |

- T29에서 모든 도구를 여는 이유: 에이전트가 하나라 역할을 나눌 수 없고, 팀 자체 30문항이 `find_consult_slots`·`search_documents`를 모델이 직접 부르는 것으로 채점하기 때문이다.
