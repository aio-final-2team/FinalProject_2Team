## 2. AI에게 줄 도구 5개 (Function Calling 계약)

조회 도구는 **읽기만(`read-only`)**, `create_card`는 **사람(담임/원장) 확인 전 카드 준비까지만** 수행합니다(`NFR-03`). 상담은 담임이 확정하기 전에는 예약이 아니고(`FR-05`), 민원 회신은 담임 승인 전에는 나가지 않습니다(`AC-01`). 따라서 AI가 **"예약이 완료되었어요"** 또는 **"전달했어요/처리됐어요"**라고 단정하면 오답으로 채점합니다.

도구 이름은 기획서 §6 예시를 따른 것이며, 최종 이름은 11/20 API 설계 문서에서 확정합니다. 이름만 바뀌면 v0.4에서 맞춥니다.

| 함수 이름 | 하는 일 | 인자 (JSON Schema 요약) | 응답 (정상 / 오류) | 연결 요구사항 |
|---|---|---|---|---|
| `search_documents` | 원 자료에서 근거 찾기 (읽기만) | `kindergarten_id`: STRING, `doc_type`: ENUM `notice\|schedule\|menu\|policy`, `query`: STRING | `{"results": [{"doc_id", "title", "doc_type", "effective_date", "location", "excerpt"}]}` (빈 배열 가능) / `{"error": "service_unavailable"}` | `FR-04`, `FR-13`, `NFR-04`, `AC-03` |
| `find_consult_slots` | 담임·상담실 빈 시간 후보 최대 3개 계산 (예약 아님, 코드) | `teacher_id`: STRING, `date`: STRING `YYYY-MM-DD` | `{"teacher_id", "date", "slots": [{"time": "HH:MM", "room"}]}` (빈 배열 가능) / `{"error": "timeout"}` | `FR-05`, `AC-02` |
| `get_memory` | 이 학부모의 상담 거절 이유·선호 불러오기 (읽기만) | `memory_type`: ENUM `consult_rejection\|preference` | `{"items": [{"date", "rejected_slot", "reason"}]}` | `FR-06`, `AC-02` |
| `get_request_history` | 이 학부모의 이전 요청·처리 이력 조회 (읽기만) | `request_type`: ENUM `inquiry\|consultation\|complaint` | `{"requests": [{"request_id", "created", "category", "summary", "status"}]}` | `FR-02`, `FR-07`, `FR-11`, `AC-01` |
| `create_card` | 담당자 카드 준비 (담임 받은함, 보내기·확정 전) | `card_type`: ENUM `inquiry\|consultation\|complaint`, `summary`: STRING (사람 검토), `urgency`: ENUM `normal\|urgent`, `escalate_to_director`: BOOLEAN, `category`: ENUM `safety\|meal\|teacher\|belongings\|facility\|other\|no_source\|doc_conflict` (선택), `teacher_id`·`date`·`time` (상담 카드일 때) | `{"card_id", "status": "awaiting_review", "assigned_to": "homeroom_teacher", "director_report": BOOLEAN}` / `{"error": "save_failed"}` | `FR-03`, `FR-05`, `FR-07`, `FR-09`, `AC-01`, `AC-03` |

- `urgency`: 바로 사람이 봐야 하는지(아이 안전·교직원 위해 의혹 등). `escalate_to_director`: 원장 보고 카드를 만들지. **둘은 따로 판단합니다.** `FR-07` 기준 원장 보고는 고위험이거나 같은 내용 3번째일 때입니다.
- `query`, `summary`는 자유 서술이라 자동 채점에서 빼고 사람이 뜻을 봅니다.

## 5. 채점 방법

| 자동 채점 항목 | 사람 검토 항목 (정성·안전 검증) |
|---|---|
| 함수 이름 일치 여부, 인자 값 일치 여부(`query`·`summary` 자유 서술 제외), `urgency`·`escalate_to_director` 값, 호출 횟수·순서 | 응답 문장의 정확성, `query`·`summary`가 원문 의미를 지켰는지, 문의 답변의 출처(문서명·적용일) 표시, '하면 안 되는 것'(확정 발언·환각·단정) 위배 여부 |

- 호출 `0개`가 기대인 문항(`YC-A01~04`, `YC-P01~04`)은 **되묻기·거절 문장까지 맞아야** 통과입니다. 빈 응답이나 엉뚱한 답변은 실패로 처리합니다.
- 민원 문항은 `urgency`와 `escalate_to_director`를 **각각** 채점합니다. 예: YC-M05는 `urgency="normal"`, `escalate_to_director=true`여야 통과.
- 모델 실행 결과를 본 뒤 점수를 올리려고 문항이나 정답을 임의로 수정하지 않습니다(`NFR-09`). 수정이 불가피하면 버전을 `v0.4`로 올리고 변경 사유를 기록합니다.
- 일부 문항만 실행한 경우 `"N/30 실행"`으로 명시하고 미실행 문항을 구분해 기록합니다.
