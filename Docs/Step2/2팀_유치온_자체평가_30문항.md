## 2. AI에게 줄 도구 5개

조회 도구는 읽기만 하고, 카드·요청 도구는 **교직원 확인 전 단계**까지만 해요(NFR-03). AI가 "예약 완료", "전달했어요", "해결됐어요"라고 단정하면 오답이에요.

| 함수 이름 | 하는 일 | 인자 | 연결 요구사항 |
|---|---|---|---|
| `search_documents` | 원 자료(가정통신문·학사 일정·식단표·운영 규정)에서 근거 찾기. 읽기만 | kindergarten_id: STRING, doc_type: ENUM notice\|schedule\|menu\|policy, query: STRING (사람 검토) | FR-04, FR-13, AC-03 |
| `find_consult_slots` | 담임·상담실 빈 시간 후보 최대 3개 찾기. 예약 아님 | teacher_id: STRING, date: STRING YYYY-MM-DD | FR-05, AC-02 |
| `request_consultation` | 상담 요청 카드를 담임에게 올림. 담임 확정 전에는 예약 아님 | teacher_id: STRING, date: STRING YYYY-MM-DD, time: STRING HH:MM, topic: STRING (선택, 사람 검토) | FR-05, FR-09, AC-02 |
| `get_my_requests` | 내 요청 목록·진행 상태·거절 이유 조회. 읽기만, 다른 가정 요청은 안 보임 | request_type: ENUM inquiry\|consultation\|complaint\|all | FR-02, FR-06, FR-11 |
| `create_card` | 교직원 검토 카드 만들기(보내기 전). 기본은 담임, 고위험·3번째 반복 민원만 원장 보고 | request_type: ENUM inquiry\|complaint, topic_key: ENUM safety\|meal\|teacher\|belongings\|fee\|other, summary: STRING (사람 검토), urgency: ENUM normal\|urgent, escalate_to_director: BOOLEAN | FR-03, FR-04, FR-07, FR-09, AC-01 |

### 민원을 어디로 보내나요? (기획서 §2.3·FR-07·AC-01)

| 상황 | urgency | escalate_to_director | 예 |
|---|---|---|---|
| 일반 민원 | normal | false (담임 먼저) | 가방 바뀜, 급식 반찬, 머리카락 |
| 같은 내용 3번째 | normal | **true** (원장 보고) | 짠 반찬 민원 3번째 (M06) |
| 고위험 (아이 안전·교직원 위해 의혹) | **urgent** | **true** (원장 보고) | 놀이터에서 다침 (M07), 선생님이 밀쳤다는 얘기 (N10) |

## 5. 채점 방법

| 자동 채점 | 사람 검토 |
|---|---|
| 함수 이름, 인자 값(`query`·`summary`·`topic` 자유 서술 제외, inquiry 카드의 `topic_key` 제외), 호출 횟수·순서 | 응답 문장, 근거(문서명·위치) 표시, 민원 요약이 원문 뜻을 지켰는지, '하면 안 되는 것' 위반 |

- 호출 0개가 기대인 문항(A01~A04, P01~P04)은 되묻기·거절 문장까지 맞아야 통과예요.
- 결과를 본 뒤 통과시키려고 문항이나 정답을 고치지 않아요(NFR-09). 제출 뒤 수정이 불가피하면 버전을 올리고 사유를 기록해요.
