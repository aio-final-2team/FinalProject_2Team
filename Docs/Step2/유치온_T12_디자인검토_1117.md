## 진단 1. 학부모 화면

Method: dual-agent (A: design review · B: detector + browser evidence)

#### Design Specificity
Content is product-specific (누리과정 tags, meal status, medication line synced to request status, "42장 중 하린이 7장"); visual language generic (white cards, grey icon chips, tile grids). Mint barely used; 말풍선 친구 character absent from parent screens.
Detector: 69 findings across 10 routes, mostly low-contrast (#a0a8bc on white 2.4:1 bottom tabs/times; #6b7590 on #f4f6fa 4.2:1 chips), undersized 10.5px labels on album, skipped headings (album, news), gray-on-color on news. requests text-occlusion x7 = false positive (open drawer). Measured: many sub-44px targets (feed 32/39, chips 28px, "관리" 22×20). 0 console errors; aria-hidden focus warning when sheet opens. All 94 imgs alt="".

#### Strengths
1. Medication sheet honesty (no guessing dosage, send blocked, report line syncs) — NFR-03, FR-14.
2. Source labels on AI answers — NFR-04.
3. Request detail stepper + next-action copy — NFR-10.

#### Priority Issues
- [P0] No free text input in ask/complaint/consult; parent words fabricated; consult time sent on single tap. Fix: input-first, chips as suggestions, confirm step for complaint/consult, pick up to 3 times then send. (/impeccable harden, /impeccable clarify)
- [P0] Cross-screen data contradictions (meetup time/place, birthday date, consult preference). Fix: single fixture keyed by event ID (apply in mock API T13). (/impeccable harden)
- [P1] Bell is not a request notification center (FR-12). Fix: separate notifications screen, status changes first. (/impeccable layout, /impeccable clarify)
- [P1] Safety states colored as success; missing required info (pickup person name/contact; medication date/symptom/consent). Fix: orange warning, required fields, "pending teacher confirmation" chip, validate on attempt. (/impeccable harden, /impeccable colorize)
- [P2] Home overload + duplicated request entry points. Fix: report → active requests; FAB opens request sheet; move 원 소식. (/impeccable distill)

#### Persona Red Flags
- Casey: consult chip tap irreversible; 4s toast, no receipt; "챙겼어요" not persisted.
- Jordan: 우리 애 vs 내 아이; alarming "학대 의심" footer; unlabeled drawer icon on /ask.
- Sam: bottom tab 11px at 2.4:1; ~30px pickup segments; empty alt on content photos; FAB without visible label.

#### Requirement gaps
/ask: request ID, status badge, missing-info follow-up (FR-02), streaming steps (NFR-10). Request detail: rejection→re-proposal (FR-06), approval-needed flag. Notifications center missing (FR-12). Feed: scope-hidden photos not shown (FR-22); 동네 tab exposure risk. /me: per-item memory delete (FR-20). Medication/pickup: unregistered handover marking, staff-confirm before complete (FR-16).

#### Minor
/ask header stays "새 요청"; bus info split 16:12 vs 15:48; "40 장으로 다음" spacing; 19 font sizes (10–22px); demo-only links in /me.

#### Questions
1. Can an inquiry app where parents can't type their own words promise "instead of the teacher's personal number"?
2. Is home's protagonist the daily report or requests?
3. Are face finding / neighborhood sharing reasons for a director to adopt, or to refuse?

#### Design Specificity
Copy and scenarios are product-specific; structure (grey cards, navy buttons, KPI tiles, bottom tabs) is generic approval-app. Brand blue only on progress bar, no mint. Director at 1280 renders inside a 390px phone frame. /teacher is an 8-week demo story (1/7 → 끝), not an operating inbox.
Detector: low-contrast on all 8 views (#a0a8bc on #fff 2.4:1 tabs; #6b7590 on #f4f6fa 4.2:1; #b7791f on #fff4de 3.3:1 확인 필요 pill; badge 3.9:1), nested-cards on director @1280. Same tokens as parent screens. Double-click on 승인: processed once (AC-05 pass), but no pending state and no aria-live announcement. No h1 on any staff screen; director heading order reversed; content photos alt="". 0 app console errors.

#### Strengths
1. Post-approval outcome panel (what was sent/scheduled).
2. Reject reason → memory → rule flow with provenance.
3. 알림장 batch-send lock matches T04 §6; doc upload staged progress.

#### Priority Issues
- [P0] AI fabricates unobserved facts (cough line in notes; outdated-source answer saved as 원에 남은 답) — NFR-03, 합의 7. Fix: choice input for health/medication lines; outdated-source cards approve as "이번만 보내기" + "올해 문서 올리기". (/impeccable harden, /impeccable clarify)
- [P0] No inbox: T04 6 filters, urgent pinning, state labels, 보류, 원장님께 올리기, 처리 완료 absent. Fix: filter chips + counts + list/single toggle, urgent pinned, [상태·담당·기한] header, approve/reject/more. Move demo story out. (/impeccable shape, /impeccable layout)
- [P1] Complaint card missing risk level, sources, repeat count, original text; completion skips parent-confirm→teacher-complete (합의 2); consult card differs from 합의 1. (/impeccable clarify)
- [P1] Irreversible actions without safeguards (batch send, director rule, reject cannot cancel, 28px 처음부터 next to progress). (/impeccable harden)
- [P2] Director dashboard non-interactive, no PC layout, missing FR-19 reassignment, delayed counts, history, eval tab, escalation conditions 2–4. (/impeccable adapt, /impeccable layout)
