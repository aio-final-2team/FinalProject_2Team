**문서·코드 차이 — 이번에 고치지 않음**

- T04 5장·T12 AC-03·계약표 `find_saved_answer`는 조건을 만족하면 바로 답하도록 적었다. API 5.3 ④·이번 5.7·T14 2.1은 담임 승인 뒤 발송이다. 30문항 YC-M08도 근거가 있으면 바로 답을 기대한다.
- T12 D-02는 원장 화면에서 민원 회신을 보내지 않는다. API 4.2와 `cards.decide`는 원장도 일반 회신 카드 결정·민원 완료를 할 수 있다. 상담 확정의 원장 거부는 코드·문서·시험이 같다.
- 30문항 YC-F04는 카드 저장 실패를 접수 실패로 안내한다. 기존 API v0.3은 요청 접수와 카드 저장을 나눠 접수됨을 유지한다. `create_card.topic_key`도 평가 6개와 계약표 주제 10개 + other가 다르다.
- T12에는 도구 이름이 없어서 API·평가와 세 문서 이름 일치를 판정할 수 없다. API·평가 공통 도구 5개 이름은 모두 같다.
- 근거 없음·문서 충돌·검사 실패의 사람 인계는 설계 계약이다. 모의 API는 근거가 없어도 모의 본문을 만들고 검사 통과를 넣으며, 충돌·검사 반복을 실제 수행하지 않는다. T14의 권한 밖 질문은 도구 호출 없이 안내한다. 이번 5.7은 지시대로 범위 안 사람 인계 기준을 모았고, 권한 밖 자료는 열지 않는다.
- T04·T14는 검사 단계로 2번 돌려보내도 실패하면 3번째에 사람에게 넘긴다. 이번 지시의 '검사 2번 실패'와 횟수 표현이 달라 남긴다. 일반 기한은 근무 시간 밖에도 세므로 `WORK_HOURS`로 기한을 자르지 않는다(기존 6.5 예시 유지).
- T14는 API v0.2를 참조하며 카드 없는 요청의 미배정 표시에 확인이 필요하다고 적었다. API 기존 v0.3의 6.3에는 서버 점검 작업 계약이 있으나, 모의 API에는 구현하지 않았다고 명시돼 있다.

OpenAPI는 `python apps/api/scripts/export_openapi.py`로 다시 생성하고 `git diff --exit-code -- contracts/openapi.yaml`로 변경 없음을 확인했다. 자동 대조 시험도 통과했다. 첫 환경에서 패키지 조합 차이로 74개 통과·OpenAPI 1개 실패가 나와, 기존 T13 시험 환경과 같은 FastAPI·Pydantic 버전으로 맞춘 뒤 기준 75개와 최종 88개가 통과했다. 스키마를 바꿔 시험을 맞추지는 않았다.
