# 기억 최종판 설계 (FR-06·FR-20)

> 이 문서는 유치온의 '내 AI 기억'을 최종 발표(1/4) 범위까지 어떻게 만들지 정한 설계예요. 지금 무엇이 있고, 무엇을 어떤 순서로 더하는지, 누구 영역과 겹치는지를 적었어요. 작성 11/26 태웅.

## 목표
쓰는 사람이 같은 말을 두 번 하지 않아도 되게 해요. 선생님 말투·선호, 학부모 선호, 아이 돌봄 정보가 대화와 결정에서 자동으로 쌓이고, 다음 답변·상담 후보·알림장이 그걸 알아서 반영해요.

## 지금 (develop `63c83d5`, 팀 서버 실측)
- memories(owner=사용자, kind 3종: rejection_reason·preference·tone) / memory_rules / saved_answers(질문 임베딩 칸 있음) 표는 있음. 서버 행 0·0·0.
- 쌓는 경로: 담임 카드 거절·반려 → rejection_reason 1종뿐(대역 문장). preference·tone을 만드는 코드 없음. 기억 AI 모델(LLM_MODEL_MEMORY) 미연결.
- 쓰는 경로: 협업 그래프가 담임 tone 기억 8개를 답변 작성에 넘김(행이 없어 빈 목록) / 상담 후보가 담임 active 규칙을 읽음. 알림장·학부모 쪽은 안 씀.
- saved_answers: 표만 있고 저장·검색 코드 없음. 조회·삭제 API(GET/DELETE /memories)는 본인 것만.

## 만들 것 — 쌓기 → 꺼내 쓰기 → 보기·지우기
### 1. 쌓기 (사람이 따로 입력하지 않음)
| 주인 | 종류(kind) | 언제 뽑나 | 예 |
|---|---|---|---|
| 담임 | tone(말투) | 초안을 고쳐서 승인(edit_approve)할 때 원문↔고친 글 비교 | "끝에 '궁금한 점은 언제든 알려 주세요'를 붙임", "해요체, 3문장 이내" |
| 담임 | preference | 거절 이유·상담 확정 패턴 | "화요일 오후엔 상담 안 잡음" (지금 있는 규칙 제안으로 이어짐) |
| 담임·반 | saved_answer | 문의 답변 카드 승인 시 질문+보낸 답 저장 | "체육복 요일" 질문의 승인 답 |
| 학부모 | preference | 상담 선호 입력, 반복되는 요청 | "상담은 평일 18시 이후 전화", "알림은 저녁에" |
| 아이(보호자 소유) | care_note(새 종류) | 보호자가 문의·투약·귀가 요청에서 직접 말한 돌봄 정보 | "달걀 알레르기", "할머니가 자주 하원", "낯가림 심함" |
- 추출은 요청·카드 처리가 끝난 뒤 워커에서 기억 AI 한 번(본 흐름을 늦추지 않음). 출력은 후보 0~2개, 코드가 형식·중복(같은 주인·같은 뜻)·민감 낱말을 검사한 뒤 저장.
- care_note만은 바로 저장하지 않고 보호자에게 "이 내용을 기억해 둘까요?" 확인을 받는다(동의 = 저장). 근거: T14 3.3 '아이 건강·가정사는 저장 안 함', 기획서 FR-20 '민감·일회성 저장 안 함'과 부딪히는 유일한 종류라 본인 확인으로 푼다. (11/26 태웅 결정: 확인받은 것만 저장)
### 2. 꺼내 쓰기 (요청마다 관련된 것만)
- 문의 답변: (a) 그 아이 care_note + 그 보호자 preference, (b) 담임 tone, (c) 비슷한 saved_answer(임베딩 유사도, 같은 반·원 전체, 근거 문서가 아직 유효한 것만) → 작성 AI 입력의 `memories[]`·`prior_answer`. 근거(자료)와 섞지 않는다: 기억은 '맞춤'에만 쓰고 사실 근거는 여전히 원 자료 인용이어야 검사 통과.
- 상담 후보: 보호자 preference를 preferred_times 기본값으로(#364의 다음 단계), 담임 규칙은 지금처럼.
- 알림장: 담임 tone + 아이 care_note(예: 알레르기 있는 날 식단 문장 주의)를 작성 입력에.
- 아이별 질문("밥 잘 먹었나요"): 그 아이의 최근 보낸 알림장(daily_notes sent)을 근거 후보로 추가 — 이건 기억이 아니라 검색 범위 확대라 따로 PR.
### 3. 보기·지우기 (FR-20, 세 역할 같은 화면)
- GET /memories가 본인 기억 + (학부모면) 자기 아이 care_note, (담임이면) saved_answers·규칙까지 한 목록으로. DELETE는 본인 것만, 지우면 다음 처리부터 안 씀(지금 deleted_at 방식 그대로). saved_answer는 끄기(off).
- 남의 것이 섞이지 않게: 모든 조회는 org+owner(+child는 보호자 관계 확인) 조건, 다른 가정 아이 이름은 지금처럼 가림.
